# 产品工作流与计划模式

## 一、适用范围

本规则适用于本目录后续新增或改写的产品文档、PRD、功能梳理、原型说明、指标方案、风险记录、会议纪要和交付产物说明。

后续生成内容应优先复用当前目录的产品工作流，不单独另起一套结构。

## 二、标准产品工作流

新增产品内容按以下顺序设计和沉淀：

1. 项目总览：明确项目名称、目标一句话、当前阶段、核心结论和待决事项。
2. 战略与背景：补充立项背景、问题定义、业务目标、项目边界和成功标准。
3. 用户与场景：明确角色、画像、核心场景、用户旅程和首版优先场景。
4. 业务流程：梳理现状流程、目标流程、状态流、异常流和跨部门协作规则。
5. 需求管理：进入需求池，完成价值分析、方案分析、优先级判断和纳入结论。
6. 产品方案：输出 PRD、信息架构、页面清单、功能规则、权限规则和验收标准。
7. 版本规划：拆分版本范围、里程碑、发布条件、非本期范围和变更管理规则。
8. 数据与指标：定义结果指标、过程指标、质量指标、埋点建议和分析口径。
9. 风险与决策：记录风险台账、关键决策、争议点、处理原则和责任归属。
10. 设计与原型：补充原型说明、页面流转、交互状态、异常状态和视觉体验要求。
11. 会议与调研：沉淀访谈记录、会议结论、证据来源和后续动作。
12. 附件与参考：保存外部资料、样例文件、截图、数据表和补充说明。

## 三、计划模式

当后续内容涉及新需求、新模块、复杂原型、跨目录更新或不确定范围时，先进入计划模式。

计划模式必须先产出以下内容：

| 项目 | 内容要求 |
| --- | --- |
| 目标 | 本次要解决的问题和交付结果 |
| 输入材料 | 已有文档、附件、原型、业务口径或待确认信息 |
| 影响范围 | 需要新增或更新的目录、文件、页面、流程和指标 |
| 执行步骤 | 按产品工作流拆成可执行步骤 |
| 待确认事项 | 业务规则、角色边界、数据来源、版本范围等未决问题 |
| 交付物 | PRD、功能梳理、原型说明、指标表、风险记录、会议纪要等 |

计划模式通过后，再进入具体文档编写、原型设计或脚本生成。

## 四、生成内容规则

- 关键结论必须落到对应文档，不只保留在沟通记录里。
- 新需求必须先进入 `04-需求管理/01-需求池.md`，再补充需求分析或专题功能梳理。
- 涉及方案设计时，必须同步更新 `05-产品方案` 下的 PRD 或信息架构。
- 涉及版本承诺时，必须同步更新 `06-版本规划/01-版本路线图.md`。
- 涉及数据统计、看板、埋点或分析口径时，必须同步更新 `07-数据与指标`。
- 涉及风险、争议、边界或关键取舍时，必须同步更新 `08-风险与决策`。
- 涉及页面、交互、状态或原型时，必须同步更新 `09-设计与原型`。
- 涉及会议、访谈或调研证据时，必须同步更新 `10-会议与调研`。

## 五、输出检查清单

每次生成内容完成前，检查以下事项：

- 是否符合当前目录的产品工作流。
- 是否明确目标用户、业务场景、流程闭环和异常处理。
- 是否标注本期范围与非本期范围。
- 是否补充版本、指标、风险和待决事项。
- 是否保留来源、假设和责任人。
- 是否能被后续 PRD、原型、开发和验收直接承接。
