## 全费用管理客户方案列表 2026年11月16日

### 策略额度流转设计

**产品定义。** 资金池在本系统中指可授权使用的管理额度，现金账户由财务系统管理。策略可能直接占用额度、调整客户预留、间接改变销售贡献，或仅改变清偿；不能统一按“策略金额扣一次池”处理。以下为产品建议规则，合同、税口径与财务授权经审批后启用。

**统一金额层次。** 来源分销售贡献、专项注入和净调拨；去向分未确认返利预留、服务预留、其他预留、待解锁、未核销占用、净确认费用和可用。应付、已付、抵扣、追偿是费用确认后的独立状态，不再次加入额度消耗。来源客户、受益客户、承担组织、收款主体分别保存。

`有效来源 + 未覆盖缺口 = 未确认客户预留 + 待解锁 + 未核销占用 + 净确认费用 + 可用额度`。缺口不是新来源，不准作为可用。包外成本不从本 SKU 总包扣；独立专项按其来源对平。方案预算是上限，不等于注资。

| 业务策略 | 影响资金的方式 | 触发与反向处理 |
| --- | --- | --- |
| 进货折扣、满额减免、组合采购优惠、沉默激活 | 先改变成交基数，再按 SKU 重算贡献及可变预留；不重复扣优惠原额 | 下单测算，签收计提；退货引用原销售与规则冲回，已确认义务不直接删除 |
| 新品试销支持 | 首批折扣同上；换货权益单列，按实际成本差和履约费确认 | 换货额度不折现、不直接当现金费用；实物交付和价差避免重复确认 |
| 采购返利、采购增长、连续采购、年度目标、回款奖励、年返 | 按客户配置先累计权益或同时预留；到期核验后入池；不足保留义务及缺口 | 跨档按累计应预留减未确认预留及累计净确认补差；已付包含在确认中，不遗漏、不重扣 |
| 动销奖励、市场补贴、陈列奖励、经销商推荐奖励 | 申请批准后可用转占用，凭证核验后占用转已用 | 未用余款结项释放；同门店、期间、序列号、推荐主体及凭证查重 |
| 运费补贴 | 正常履约成本已经包含的不再扣包，新增专项客户支持按批准来源占用 | 核对订单和物流账单，退货不等于服务费自动可退，按实际履约调整 |
| 库存价保或调换 | 核验原采购与库存后确认新增补偿；已通过销售折让处理的金额不再扣包 | 保留原订单、批次及调价依据，冲销与追偿单独审批 |
| 买赠满赠 | 按批准成本占用，验收使用成本转确认；数量与金额双记录 | 出库不重复确认，退库关联原出库及成本；未核销释放，已核销走冲销 |
| 合同扣点 | 明确付款、扣款及成本方向，默认不新增费用或恢复预算 | 清偿扣款与真实费用冲减分开；只有批准的费用冲销能释放管理额度 |

**生命周期事件。** 草稿和测算不记账，政策或方案发布不注资。销售按获取规则选择即时入池或先记待入池；客户费用按时点配置选择仅累计权益或同时预留来源，不能统一提前扣除所有年返。已入池可支配来源按组织比例分配。申请最终审批占用；活动核销把占用转已用；返利或服务确认把预留转已用。结项仅释放未使用承诺。结算把确认费用转应付，支付或抵扣清偿应付，二者均不再次扣池。

**金额例子。** 以贡献 10,000、返利预留 2,000、服务预留 1,000、已确认 3,500、占用 500、可用 3,000 为演示期初。新活动占用 1,000 后可用 2,000；实际核销 600 时仅占用转已用，可用仍为 2,000；结项释放 400 后可用 2,400；后续结算、支付这 600 不改变 2,400。选择提前预留来源时，年返累计应预留升至 4,000，已预留 2,000 且已确认年返为零时，只补提 2,000；已确认年返中即使部分已支付，也仍从累计应预留中扣除。

**重叠和累计控制。** 先按有效政策匹配、排除及叠加规则确定适用项，再逐项按各自基数、期间、税口径及成本口径算金额。订单让利先于费用包；同类返利择优或互斥由批准政策明确。单笔、客户累计、方案、策略及费用池上限同时校验；不能将季度、年度和单笔预估简单相加当作本次应付。同一义务只能预留或占用一处，转确认不新增一笔扣减。

**组织与跨客户流转。** 额度解锁后按批准版本分配到总部、中心、大区、省区。多池承担分别授权，最终一次原子占用。调拨同时形成调出、调入流水，汇总不生成新余额；客户 A 贡献支持 B 时，来源仍为 A、受益为 B。价格调整或返利补提不能强制收回其他活动已用金额，缺口挂账后走补足或批准调整。

**退货、退款与期末。** 退货先调整来源销售，再按原合同判断哪些预留可释放。未核销活动及未使用物料只能释放本项目剩余占用；已确认费用走原单冲销。已支付不能当作未支付直接删除，先记录待追偿、退款或抵扣恢复，再按批准方向调整管理费用。退款到账不当然代表可用预算恢复；关账期不覆盖，在开放期调整并保留原业务期间。

**账本与接口要求。** 每条事件至少关联法人、币种、来源账户、费用类型、客户与组织、策略及方案版本、来源销售行、业务单据、项目、业务期间、入账期间、事件类型、版本、金额税口径、前后状态及原冲销记录。按来源系统、单据行、事件类型及版本幂等；一次拆分整体成功或失败。审批提交时锁定余额与累计上限，重放不能产生第二笔费用。实际应付和支付应逐明细关联，不能借用其他客户或其他费用类别的金额。

**异常与权限。** 新活动余额不足不占用；合同预留不足不能少计义务，登记缺口、冻结相关新增释放并走补足。包内包外或专项归属不得临时切换。注资、调拨、预留释放、费用冲销、追偿和收款变更分别授权，不自批。策略调整采用新版本及差额事件，已批准承诺保留原版本；批量重算先预览影响及缺口后审批。

**界面验收。** 策略详情显示承担来源、预留或占用节点、费用确认节点、结算方向、退货恢复及缺口规则；方案测算列出每个策略对贡献、预留、占用、已用和可用的差额。审核页展示本次影响前后对比及来源。组织费用池提供 19 类策略矩阵和隔离流转沙盘，演示跨档补提、占用核销释放、支付不重扣、实物成本、退货缺口、专项补足及重复事件拦截。

**沙盘边界。** “额度流转沙盘”在独立会话中模拟上述事件，不能向真实业务账本、现金账户或第三方系统写入。示例使用客户 A 比例费用及明确的演示期初；固定服务费、不同税口径和复杂跨期合同不能直接套比例。其余客户及独立专项账户需具备自己的来源和期初后才能正式计算，不使用客户 A 余额冒充。

客户活动策略整合：新增“客户活动方案 / 策略库”入口，复用客户及商业政策主键。活动方案保存适用客户、商业政策版本、期间、组合关系、预算与客户及单次上限，内嵌 19 类规则快照、参数和独立测算输入。执行版本与变更候选分离，统一审核工作台列示方案审批，中心池负责人 → 财务 → 业务复核后生效；驳回或撤回保留记录。

客户及政策详情可下钻活动方案、试算、执行及清偿。试算可引用活动方案快照；执行单保存方案编号、版本和策略，按原活动审批占用、核销、结项释放和清偿，客户台账同步体现。方案额度不是账户资金，市场执行需同时满足方案、客户、单次及承担池上限。订单价格优惠不重复扣包，返利按客户预留处理，实物需库存成本，合同扣点不当作奖励。资格及真实 OA、OMS、库存接入仍为原型边界。

客户费用总台账补充：入口为客户列表，展示客户编码、中心及模式、有效销售、总贡献、已确认投入、来源活动可用、实际受益投入和台账状态。支持搜索及筛选，点击进入独立客户详情，保留返回上下文和可恢复地址。客户 A 延用现有账本；其他演示客户未导入销售期初，相关金额以 — 显示。跨客户支持保留来源和受益两维度，不将受益金额当作该客户来源贡献或新增可用余额。详情政策与试算操作关联所选客户。

页面流转补充：政策与试算均采用“列表 → 独立查看或编辑 → 保存成功返回原列表”，试算结果与输入在同一独立详情内并列。活动申请、活动明细与审核、核销表单同样独立展示；清偿登记保留轻量弹窗。详情提供顶部返回、面包屑、可恢复 hash 地址、未保存离开提醒，返回保留列表筛选与滚动位置；输入错误不跳走或清空。独立页是同一 HTML 中的路由页面，不额外打开浏览器标签页。

- 客户政策入口改为方案列表，展示方案编号及名称、客户、业务模式、承担中心、合同及 SKU 范围、版本、有效期、费率和状态。支持搜索、按客户及状态筛选、新建草稿、编辑草稿、复制新版本和引用试算。已生效方案只能查看；新版本不覆盖历史。
- 销售费用试算入口改为试算方案列表，展示客户、引用政策及版本、有效销售基数、费用贡献、客户预留、可解锁额度和保存时间。支持新建、打开、复制、编辑与本地保存。
- 一名客户可关联多套政策及多个版本，按合同项目和业务模式区分。试算选择客户后仅列出其政策，选择政策带入费率、中心及分配比例；草稿可用于评审试算，并显著标识未发布。试算允许覆盖费率进行情景比较，但不修改政策。
- 试算保存独立参数快照，后续编辑政策草稿不回改已保存试算。切换客户时重新选择对应政策，校验客户与快照一致，防止串用参数。
- 校验覆盖必填信息、日期先后、分配比例合计 100%、同客户合同版本重复、退货超签收、政策冲突和超包。失败保留输入，筛选无结果提供清除入口。原型演示客户与角色不构成生产客户主数据及权限。
- 旧本地数据保留：原参数草稿迁移为客户 A 独立草稿，已生效 POL-001 / V1、费用台账、活动与清偿记录保持原值。其他客户方案为新增演示样例，不产生新账本余额。

## 资金获取与客户策略延期入池（2026年11月17日）

本章补齐用户确认的核心目标：先设总资金池和获取方式，完成销售后增加来源；客户策略决定权益金额、来源及何时入池。前文“销售即预留”仅适用于明确选择提前预留的配置，年返可以只记录到年底。当前金额是费用管理额度，不能当作银行现金余额。

### 对象与关系

经营总资金池 ← 销售获取规则 ← 有效签收销售行；客户 → 商业政策 → 客户资金策略版本 → 期间权益 → 核验批次 → 客户返利专属池 → 返利清偿。活动方案内提供资金策略入口，19类策略的业务条件与测算继续保留；年返测算不能作为另一份金额再累计，实际返利统一引用客户资金策略版本。源净销售已经承接订单让利，不再扣同一笔价格优惠。

| 配置对象 | 必要字段 | 生效与控制 |
| --- | --- | --- |
| 经营资金池 | 名称、初始来源、预算上限、有效期、总部/中心/大区/省区比例 | 财务保存草稿并启用，比例合计100%；启用后初始来源及比例固定，避免历史重分配；上限不能低于有效来源 |
| 销售获取规则 | 目标池、适用客户、SKU、金额比例/每数量金额/单笔阶梯、即时/月末/季末/年末、期间、版本 | 同行唯一匹配；冲突或无规则均拦截；延期获取不提前形成余额，超过上限记录待处理并可重试 |
| 客户资金策略 | 客户及商业政策、来源池、固定返利率/累计阶梯、达档全额/分段、服务预留率、核验时点、是否提前预留、有效期、版本 | 商业政策必须属于客户且生效；来源与获取池一致。支持即时、月、季、年末；累计阶梯限期间方式，门槛下0%，分段仅对超过门槛区间计提 |
| 销售事件 | 来源单号、行号、客户、SKU、不含税净额、数量、业务日、退货原行 | 单号+行号+事件类型防重复，保存规则及政策快照，退货不晚于模拟业务日、不早于原销售且不得超退 |
| 核验批次 | 期间、净销售、累计应享、已释放、本次差额、明细签名、审批记录 | 截止日前禁提；销售申请→业务复核→财务复核；不自批，明细变更后先驳回重报 |
| 清偿事件 | 批次、客户返利池、现金/货款抵扣、金额、财务回写流水号 | 财务登记，回写号查重，不超过批次剩余及专属池余额 |

### 三个时点分别控制

1. **权益累计**：签收销售及退货增加或减少客户期间净销售，计算预计应享。此时既不代表总池增加，也不代表客户收到款；总池是否增加由独立的销售获取规则决定。
2. **入池/释放**：获取规则若延期，则期末审批才增加经营池；客户年返到年末核验、批准后从经营来源池转到客户返利专属池，形成可结算返利应付。内部划拨保持公司总来源不变。
3. **发放**：在“结算与清偿”登记现金支付或货款抵扣，减少客户返利池未清偿额度，保留来源、核验及付款链。不能再从经营池重复扣减同一笔返利。

“先记录”模式不提前锁总池，因此要显示尚未入池的客户权益，并在期末进行来源及四级组织余额校验；不足时权益保留，批次待处理。“先记录并预留”模式按累计未释放差额锁定来源，可用经营额度提前减少，到期转池时释放对应预留，不重复扣款。两种模式均不提前增加客户返利池。

### 金额演示与迁移

原演示客户A有10万元期初销售、1万元有效来源，其中年返预留2000元、服务未确认1000元、已确认费用3500元、占用500元、可用3000元。迁移仅承接已知销售和年返权益，不重复计提1万元来源；其他客户没有期初数据时不推断余额。

在2026-11-17新增A签收销售10万元，获取率10%、服务预留3%、年返2%且先记录：经营池新增1万元，服务预留新增3000元，可用从3000变成10000元；全年应享年返合计4000元（期初2000+本次2000），客户返利池仍为0。年末核验后转入专属池4000元，同时解除对应期初已锁2000元，来源池可用8000元。发放1000元后，客户返利池剩余3000元，经营池仍为8000元。

### 调整、版本与异常

- 配置修改形成新版本，按销售日期匹配；旧销售和退货继续使用原快照。年度统计按客户、策略版本、期间分组，不把不同版本阶梯混成一个口径；追溯改变旧合同需另走差额审批。
- 待入池前退货减少原期间净销售及应享，阶梯按原单剩余金额重算获取差额。受上限阻塞的原单退货不先扣未曾入池的资金，重试时仅按剩余净额生成一笔来源。
- 释放前的统计变化使原批次失效，审批拦截后可驳回重报。释放后应享减少时保留负差额和原转池记录，暂停相关批次继续发放；未付冲销、已付追偿及退款后审批冲回属于待办处理，当前不自动恢复资金。
- 经营池可用=初始来源+有效销售入池−转出客户返利池−未确认预留−已确认费用−未核销占用；不足显示缺口。返利池可结算=批准划入−已发放。跨池内部流转不能增加汇总来源。
- 客户列表的来源池可用为共享池余额，不能跨客户相加；销售贡献、客户返利权益和实际受益分别展示。返利专属池不允许普通市场活动申请。

### 交付与未接入项

“资金池与获取”提供总资金池、资金获取规则、客户策略与时点、销售入池、期间结算、入池与划拨流水六个页签。客户、商业政策及活动方案可下钻客户资金策略，审核工作台接期间核验，结算与清偿接客户返利发放，原组织余额与活动申请同步读取销售入池结果。配置、销售与核验均为独立业务页，轻量发放保留弹窗，失败保留输入。

本轮是可运行的浏览器本地账本闭环，真实OMS签收事件、ERP应付/付款、银行、库存、法人及币种、自动定时核验、关账期管理、全部19类策略自动资格判定与正式调整审批仍需研发接入。模拟业务日用于演示年底，不可作为生产系统绕过期间控制的设计。

## 命名规范

- 模块命名原则：对外协作统一使用 `运营中心`，避免在页面中混用合作商、代理商、中心等名称。
- 代理发货管理命名原则：若业务侧明确使用 `代理发货`，页面可保留该名称；底层对象仍建议与运营中心履约体系复用同一套合作方、区域、商品和库存配置。
- 打样反馈命名原则：二维码、反馈记录必须绑定 `样品批次`，页面中避免只说商品二维码，防止配方版本和包装版本混淆。
- 页面命名原则：以业务对象命名，如 `运营中心订单`、`补货单`、`签收凭证审核`。
- 状态文案原则：使用可执行、可理解的状态，如 `待接单`、`待发货`、`凭证待审核`、`待生成补货`、`补货在途`。
