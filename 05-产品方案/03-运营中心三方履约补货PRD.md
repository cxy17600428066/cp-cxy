# PRD：运营中心三方履约与补货

**状态**：Draft  
**版本**：V0.1  
**日期**：2026-04-30  
**适用对象**：卓希集团、合作商/运营中心、客户  
**关联需求文档**：`../04-需求管理/04-三方订单履约与补货功能梳理.md`

## 1. 问题陈述

客户下单后，若合作商已有现货，合作商可以更快完成本地发货。但当前缺少一套系统化机制来承接三方协同：

- 卓希无法集中看到合作商承接了哪些客户订单。
- 合作商发货、物流、签收凭证依赖线下沟通，过程不可追踪。
- 卓希给合作商补货缺少和客户订单、实际发货、签收凭证的强关联。
- 订单履约和补货之间容易出现漏补、重补、数量不一致和责任不清。

本功能要解决的问题是：建立 `客户订单 -> 运营中心履约 -> 物流签收 -> 卓希补货` 的业务闭环。

## 2. 目标与成功指标

| 目标 | 指标 | V1 目标 |
| --- | --- | --- |
| 提升客户履约效率 | 运营中心订单平均发货时长 | 低于原总部发货平均时长 |
| 降低人工沟通成本 | 线下催物流/要凭证次数 | 明显下降，可通过运营记录统计 |
| 提升补货准确性 | 重复补货/漏补货次数 | 试运行期可人工复核，目标为 0 |
| 建立履约可追溯 | 运营中心订单关联完整率 | 客户订单、物流、凭证、补货单关联率 100% |
| 提升合作商协同效率 | 签收凭证及时率 | 签收后规定时间内上传或确认 |

## 3. 非目标

V1 不做以下内容：

- 不做复杂的多运营中心智能调度算法。
- 不做自动结算和财务对账。
- 不做完整 WMS 库存批次管理。
- 不做客户侧复杂的运营中心品牌展示。
- 不做售后责任自动判定。
- 不强依赖第三方物流轨迹自动同步，V1 可先人工回填。

## 4. 用户与场景

### 4.1 卓希订单运营

作为卓希订单运营，我希望看到所有由运营中心承接的客户订单，以及每个订单的接单、发货、签收、凭证和异常状态，以便及时催办和处理异常。

### 4.2 运营中心人员

作为运营中心人员，我希望只看到分配给自己的订单，并能快速确认接单、填写物流、上传签收凭证，以便完成履约并获得卓希补货。

### 4.3 卓希供应链人员

作为卓希供应链人员，我希望系统基于已签收且审核通过的订单生成补货单，以便准确给运营中心补回库存。

### 4.4 管理者

作为管理者，我希望看到运营中心履约效率、异常率和补货状态，以便判断合作商履约质量。

## 5. 方案概述

系统新增 `运营中心履约` 能力。客户订单确认后，系统根据商品、区域、运营中心库存和合作状态判断是否可由运营中心发货。若满足条件，生成运营中心订单，并由运营中心完成接单、发货、物流回填和凭证上传。

卓希集团在后台统一查看运营中心订单状态。签收凭证审核通过后，系统生成补货单，补货单关联客户订单、运营中心订单、商品明细、实际发货数量和签收凭证。供应链人员确认后安排补货，运营中心收到补货后确认入库，闭环结束。

V1 建议采用 `系统推荐 + 卓希人工确认` 的分配模式，避免库存数据不准导致错误派单。

## 6. 功能范围

### 6.1 本次范围

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 运营中心订单 | 生成、查看、筛选、详情 | 承接客户订单履约过程 |
| 接单发货 | 确认接单、拒绝、物流回填 | 面向运营中心 |
| 签收凭证 | 上传、审核、驳回、重传 | 作为补货依据 |
| 补货单 | 生成、确认、发货、入库 | 面向卓希供应链和运营中心 |
| 异常处理 | 缺货、超时、物流异常、凭证异常 | 支持备注、改派、关闭 |
| 配置 | 运营中心、服务区域、可履约商品 | V1 可轻量配置 |
| 日志 | 关键操作留痕 | 接单、发货、审核、补货均记录 |

### 6.2 不包含范围

- 自动财务结算。
- 合作商绩效评分。
- 自动生成结算账单。
- 复杂库存批次、效期、仓位管理。
- 客户侧完整履约方展示策略。

## 7. 功能设计

### 7.1 运营中心订单生成

| 规则 | 说明 |
| --- | --- |
| 来源 | 客户订单确认后触发 |
| 生成条件 | 商品支持、区域匹配、运营中心状态正常、库存满足 |
| 生成结果 | 生成运营中心订单，关联客户订单 |
| 分配方式 | V1 支持系统推荐、卓希人工确认 |
| 库存处理 | 分配后锁定或标记预占运营中心库存 |

验收标准：

- 给定客户订单满足运营中心履约条件，系统可以生成运营中心订单。
- 运营中心订单必须关联来源客户订单和商品明细。
- 不满足条件的订单不能进入运营中心履约。

### 7.2 运营中心接单

| 功能 | 说明 |
| --- | --- |
| 查看待接单 | 运营中心只看自己的订单 |
| 确认接单 | 接单后状态变为待发货 |
| 拒绝接单 | 必须填写原因，订单回到卓希待处理 |
| 超时提醒 | 超过配置时限提醒运营中心和卓希订单运营 |

验收标准：

- 运营中心只能操作自己名下订单。
- 拒绝接单必须记录原因。
- 接单操作必须记录操作人和时间。

### 7.3 发货与物流

| 功能 | 说明 |
| --- | --- |
| 填写物流 | 物流公司、单号、发货时间、件数 |
| 上传发货图片 | 可选，用于留痕 |
| 部分发货 | 支持按商品明细填写实际发货数量 |
| 修改物流 | 允许修改，但必须保留日志 |

验收标准：

- 已接单订单可以填写物流并变为已发货。
- 物流单号为空时不能提交发货。
- 实际发货数量不能超过分配数量。

### 7.4 签收凭证

| 功能 | 说明 |
| --- | --- |
| 上传凭证 | 支持图片、PDF 或系统允许的附件类型 |
| 凭证审核 | 卓希审核人员审核通过或驳回 |
| 驳回重传 | 运营中心收到驳回原因后可重新上传 |
| 凭证关联 | 凭证关联运营中心订单和物流记录 |

验收标准：

- 没有签收凭证或签收确认的订单不能生成正式补货单。
- 凭证审核通过后，订单进入可补货状态。
- 凭证驳回后，需要显示驳回原因。

### 7.5 补货单生成

| 功能 | 说明 |
| --- | --- |
| 自动生成草稿 | 凭证审核通过后生成补货单草稿 |
| 人工确认 | 卓希供应链确认补货数量和发货方式 |
| 来源追溯 | 补货单关联客户订单、运营中心订单、凭证 |
| 防重复 | 同一运营中心订单只允许存在一个有效补货单 |

验收标准：

- 补货单数量默认等于审核通过的实际签收数量。
- 补货单可以追溯到来源客户订单和运营中心订单。
- 已生成有效补货单的订单不能重复生成。

### 7.6 补货执行

| 功能 | 说明 |
| --- | --- |
| 确认补货 | 卓希供应链确认补货单 |
| 补货发货 | 记录补货物流信息 |
| 运营中心入库 | 运营中心确认收到补货 |
| 完成闭环 | 补货单状态变为已入库/已完成 |

验收标准：

- 补货发货后可查看物流信息。
- 运营中心确认入库后，补货单完成。
- 入库数量与补货数量不一致时进入异常。

## 8. 权限设计

| 功能 | 卓希订单运营 | 卓希审核 | 卓希供应链 | 运营中心 | 管理者 |
| --- | --- | --- | --- | --- | --- |
| 查看全部运营中心订单 | 可 | 可 | 可 | 不可 | 可 |
| 查看本运营中心订单 | 不适用 | 不适用 | 不适用 | 可 | 不适用 |
| 分配/改派订单 | 可 | 不可 | 不可 | 不可 | 可 |
| 接单/拒单 | 不可 | 不可 | 不可 | 可 | 不可 |
| 填写物流 | 可 | 不可 | 不可 | 可 | 不可 |
| 审核签收凭证 | 不可 | 可 | 不可 | 不可 | 可 |
| 生成补货单 | 可 | 可 | 可 | 不可 | 可 |
| 确认补货发货 | 不可 | 不可 | 可 | 不可 | 可 |
| 确认补货入库 | 不可 | 不可 | 可查看 | 可 | 可 |

## 9. 数据与日志要求

### 9.1 必须留痕的操作

- 运营中心订单生成。
- 卓希确认分配或改派。
- 运营中心接单、拒单。
- 物流信息提交和修改。
- 签收凭证上传、审核、驳回。
- 补货单生成、确认、发货、入库。
- 异常标记、关闭和备注。

### 9.2 核心关联关系

```text
客户订单
  -> 运营中心订单
    -> 物流记录
    -> 签收凭证
    -> 补货单
      -> 补货物流
      -> 运营中心入库记录
```

## 10. 异常处理

| 异常 | 触发条件 | 处理方式 |
| --- | --- | --- |
| 运营中心缺货 | 接单前或发货前发现无货 | 拒单、改派或回退卓希发货 |
| 接单超时 | 超过配置时限未确认 | 提醒，允许卓希改派 |
| 发货超时 | 接单后超时未发货 | 预警，必要时改派或关闭 |
| 物流异常 | 物流停滞、退回、丢件 | 暂停补货，人工处理 |
| 凭证驳回 | 凭证不清晰或不合规 | 运营中心重传 |
| 数量不一致 | 发货、签收、补货数量不一致 | 人工复核 |
| 重复补货 | 同一来源订单已有有效补货单 | 系统阻断 |

## 11. 上线策略

### 11.1 V0.1 试运行

- 选择少量运营中心和商品试点。
- 采用人工确认分配。
- 补货单先生成草稿，由供应链人工确认。

### 11.2 V1.0 正式上线

- 扩展到稳定合作的运营中心。
- 固化订单、凭证、补货流程。
- 建立履约指标看板和异常预警。

### 11.3 回滚标准

出现以下情况应暂停自动生成补货单：

- 运营中心库存准确率无法支撑派单。
- 签收凭证审核争议频繁。
- 重复补货或漏补货连续出现。
- 订单履约时效低于原流程且无法解释。

## 12. 待确认问题

1. 运营中心库存数据来源是否可信，是否支持实时查询？
2. 客户订单是否可能拆分给多个运营中心？
3. 补货单是否需要进入现有 ERP / 仓配系统？
4. 是否存在冷链、温层、保质期等强约束商品？
5. 运营中心拒单后，改派规则由系统自动还是卓希人工处理？
6. 补货是否参与财务结算，本期是否需要预留字段？
7. 签收凭证保存周期和合规要求是什么？
