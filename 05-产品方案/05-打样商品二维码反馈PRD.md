# PRD：打样商品二维码反馈

**状态**：Draft  
**版本**：V0.1  
**日期**：2026-05-13  
**适用对象**：产品、研发、品控、销售/渠道、管理者、试吃用户  
**关联需求文档**：`../04-需求管理/06-打样商品二维码反馈功能梳理.md`

## 1. 问题陈述

卓希食品新品打样后，需要通过《样品品尝评定表》判断样品在感官、口味、综合评定和最终结论上的表现。当前反馈多来自纸质表格、微信、口头沟通等线下方式，无法稳定关联到具体商品批次和配方版本，后续筛选、统计、复盘和研发调整成本较高。

本功能通过在打样商品出厂时贴上反馈二维码，让试吃用户扫码按样品品尝评定表提交反馈，后台按商品、样品批次、感官评定、口味评定、综合评定、最终结论和处理状态进行列表展示与分析。

## 2. 目标与成功指标

| 目标 | 指标 | V1 目标 |
| --- | --- | --- |
| 提高反馈收集效率 | 反馈率 | 样品投放后可按批次统计 |
| 提升反馈质量 | 必填字段完整率 | 有效反馈关键字段完整 |
| 支撑研发调整 | 不认可项建议完整率 | 不认可项必须填写优化建议 |
| 支撑批次复盘 | 商品/批次关联完整率 | 100% 反馈关联商品和批次 |
| 降低人工整理成本 | 导出与列表筛选能力 | 产品/研发可自助查看 |

## 3. 非目标

V1 不做以下内容：

- 不做正式售后评价系统。
- 不做营销抽奖或会员积分。
- 不做一物一码防伪追溯。
- 不强依赖微信授权登录。
- 不做自动情感分析和 AI 总结。
- 不打通生产配方系统，先保留批次字段。

## 4. 用户与场景

### 4.1 试吃用户

作为试吃用户，我希望扫码后能快速看到这是哪款样品，并用简单方式反馈是否好吃、哪里需要改、是否愿意购买。

### 4.2 产品人员

作为产品人员，我希望按商品和样品批次查看反馈列表、感官认可率、口味认可率、综合认可率和最终结论分布，以便判断是否进入复样或试产。

### 4.3 研发人员

作为研发人员，我希望看到用户对口味、辣度、咸度、口感和腥味的反馈，以便调整配方。

### 4.4 品控人员

作为品控人员，我希望快速发现批次异常反馈，如异味、漏包、胀包、口感异常，以便排查样品质量。

### 4.5 销售/渠道人员

作为销售或渠道人员，我希望查看经销商、门店和客户对样品的反馈，以便判断渠道接受度。

## 5. 方案概述

系统新增 `打样商品二维码反馈` 模块，包含后台管理和移动端反馈页。

后台创建打样商品和样品批次后，生成绑定该批次的二维码。工厂将二维码贴到样品包装上，用户扫码进入反馈页，系统自动带出产品名称、制样日期和批次信息。用户按表格提交感官评定、口味评定、综合评定、最终结论和优化建议后，后台生成反馈记录，供产品、研发、品控和销售筛选、处理、导出和复盘。

V1 推荐采用 `一批次一个二维码`，原因是实现简单、适合打样阶段，并能区分配方版本。后续如果需要追踪每包样品，可升级为一物一码。

## 6. 功能范围

### 6.1 本次范围

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 打样商品 | 新增、编辑、列表、阶段管理 | 管理新品打样对象 |
| 样品批次 | 新增、编辑、二维码生成、启停 | 管理生产日期、配方版本、投放对象、邮寄次数 |
| 二维码 | 生成、预览、下载、停用 | 绑定样品批次 |
| 移动反馈页 | 产品名称、制样日期、评定日期、感官、口味、综合评定、最终结论 | 用户扫码填写 |
| 反馈列表 | 筛选、排序、列表展示、导出 | 后台核心页面 |
| 反馈详情 | 查看完整反馈、图片、处理状态、标签 | 产品/研发处理 |
| 统计看板 | 反馈数、认可率、最终结论分布、不认可建议 | 批次复盘 |

### 6.2 不包含范围

- 正式商品评价系统。
- 微信授权和会员体系。
- 一物一码追溯。
- 自动生成研发任务。
- 自动同步生产批次。
- 视频反馈上传。

## 7. 功能设计

### 7.1 打样商品管理

| 功能 | 说明 |
| --- | --- |
| 新建商品 | 填写商品名称、分类、口味方向、规格、负责人 |
| 编辑商品 | 修改基础信息 |
| 阶段管理 | 打样中、复样中、小批量试产、暂停、已转正 |
| 查看批次 | 查看该商品下所有样品批次 |

验收标准：

- 可以创建无骨鸡爪类打样商品。
- 商品可以关联多个样品批次。
- 商品阶段变更需要记录操作人和时间。

### 7.2 样品批次管理

| 功能 | 说明 |
| --- | --- |
| 新建批次 | 填写批次编号、配方版本、包装版本、生产日期、投放对象、邮寄次数 |
| 批次列表 | 展示投放数量、邮寄次数、反馈数量、认可率、二维码状态 |
| 批次结论 | 标记继续优化、进入复样、小批量试产、暂停 |
| 批次详情 | 查看二维码、反馈统计、反馈列表 |

验收标准：

- 每个反馈二维码必须绑定样品批次。
- 批次可以查看扫码次数、反馈数量、感官认可率、口味认可率和综合认可率。
- PC 后台样品批次列表必须展示该样品批次的邮寄次数。
- 已复盘批次可以保留历史数据。

### 7.3 二维码生成与管理

| 功能 | 说明 |
| --- | --- |
| 生成二维码 | 为样品批次生成反馈链接和二维码 |
| 下载二维码 | 支持 PNG 下载或复制链接 |
| 启用/停用 | 控制是否允许继续提交 |
| 有效期 | 可选设置反馈截止日期 |

验收标准：

- 二维码链接可以正确打开对应批次反馈页。
- 停用二维码后，用户扫码看到反馈已结束。
- 后台可以看到扫码次数和提交次数。

### 7.4 移动反馈页

| 功能 | 说明 |
| --- | --- |
| 基础信息 | 产品名称、制样日期、评定日期 |
| 感官评定 | 认可 / 不认可 |
| 感官优化建议 | 感官不认可时必填 |
| 口味评定 | 认可 / 不认可 |
| 口味优化建议 | 口味不认可时必填 |
| 综合评定 | 认可 / 不认可 |
| 最终结论 | 直接推进 / 优化后再评 / 放弃开发 |
| 评定人 | 可选 |
| 联系方式 | 可选，用于反馈跟进 |

验收标准：

- 用户可以在手机上按样品品尝评定表完成反馈。
- 必填项缺失时不能提交。
- 感官或口味选择不认可时，对应优化建议缺失不能提交。
- 提交成功后展示感谢页和反馈编号。
- 页面不暴露后台管理信息。

### 7.5 反馈列表

| 功能 | 说明 |
| --- | --- |
| 筛选 | 商品、批次、感官评定、口味评定、综合评定、最终结论、状态、时间 |
| 表格展示 | 反馈编号、商品/批次、感官、口味、综合、最终结论、建议摘要、时间、状态 |
| 批量操作 | 标记已读、添加标签、导出 |
| 排序 | 按提交时间、最终结论、不认可项数量排序 |

验收标准：

- 后台可以看到所有有效反馈。
- 可以按样品批次筛选反馈。
- 可以快速定位不认可反馈和放弃开发反馈。
- 支持导出当前筛选结果。

### 7.6 反馈详情与处理

| 功能 | 说明 |
| --- | --- |
| 查看详情 | 产品名称、制样日期、评定日期、感官、口味、综合评定、最终结论、优化建议 |
| 处理状态 | 未读、已读、跟进中、已采纳、无效 |
| 后台标签 | 研发调整、包装问题、质量风险、渠道机会等 |
| 处理备注 | 记录处理意见 |

验收标准：

- 查看反馈详情后可更新处理状态。
- 处理状态变更记录操作人和时间。
- 已采纳反馈必须填写采纳说明。

### 7.7 统计看板

| 指标 | 说明 |
| --- | --- |
| 反馈总数 | 当前筛选条件下的反馈数量 |
| 感官认可率 | 感官选择认可的反馈占比 |
| 口味认可率 | 口味选择认可的反馈占比 |
| 综合认可率 | 综合评定选择认可的反馈占比 |
| 最终结论分布 | 直接推进、优化后再评、放弃开发占比 |
| 不认可反馈 | 任一评定维度选择不认可的反馈 |

验收标准：

- 看板数据随筛选条件变化。
- 批次详情能看到该批次的反馈统计。
- 不认可项和最终结论可点击进入对应反馈列表。

## 8. 状态设计

### 8.1 样品批次状态

```text

  -> 收集中
  -> 已停用
  -> 已复盘
```

### 8.2 反馈处理状态

```text
  -> 已读
  -> 跟进中
  -> 已采纳
  -> 无效
```

## 10. 数据与日志要求

### 10.1 必须留痕

- 打样商品创建、编辑、阶段变更。
- 样品批次创建、编辑、结论变更。
- 二维码生成、启用、停用。
- 用户反馈提交。
- 反馈处理状态变更。
- 后台标签和处理备注变更。
- 数据导出。

### 10.2 核心关联关系

```text
打样商品
  -> 样品批次
    -> 反馈二维码

        -> 处理记录
```

## 12. 上线策略

### 12.1 V0.1 试运行

- 选择 2 到 3 个无骨鸡爪打样商品。
- 每个商品创建 1 到 2 个样品批次。
- 按批次生成二维码并贴到样品包装。
- 收集内部试吃和渠道客户反馈。

### 12.2 V1.0 正式上线

- 扩展到所有新品打样。
- 固化样品品尝评定表字段。
- 建立批次复盘和导出模板。

### 12.3 回滚标准

出现以下情况应暂停扩大使用：

- 二维码贴错批次，导致反馈无法追溯。
- 用户填写率过低，表单需要重新压缩。
- 反馈字段无法支持研发判断。
- 隐私字段收集口径未确认。

## 13. 待确认问题

1. 样品二维码由系统下载后人工贴标，还是需要对接标签打印机？
2. 用户反馈是否匿名即可，还是需要手机号/微信身份？
3. 反馈表单是否允许上传图片？
4. 反馈对象是否包含终端消费者？
5. 反馈导出是否需要固定 Excel 模板？
6. 批次编号是否沿用生产批号？

## 14. 验收标准

- 后台可以创建打样商品和样品批次。
- 样品批次可以生成二维码并启用/停用。
- 二维码可以打开对应商品批次的移动反馈页。
- 用户可以提交感官、口味、综合评定、最终结论和优化建议。
- 反馈记录自动关联商品、批次和二维码。
- 后台反馈列表可以筛选、查看详情、处理状态和导出。
- 统计看板可以展示反馈数量、感官认可率、口味认可率、综合认可率和最终结论分布。
- 二维码停用或过期后不能继续提交。
