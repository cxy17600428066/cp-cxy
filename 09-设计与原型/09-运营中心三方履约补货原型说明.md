# 运营中心三方履约补货原型说明

## 一、设计目标

本功能是 B 端协同履约工具，视觉和交互应优先服务于效率、准确性和可追溯。

设计目标：

- 让卓希集团快速识别哪些运营中心订单需要处理。
- 让运营中心用最少步骤完成接单、发货、凭证上传。
- 让补货单生成依据清晰可查，避免误补、重补、漏补。
- 让订单、物流、签收凭证、补货单在一个详情页形成完整链路。

## 二、整体信息架构

建议主导航新增或归入：

- `订单履约`
  - 运营中心订单
  - 签收凭证审核
  - 异常订单
- `补货管理`
  - 补货单
  - 补货发货
  - 补货入库确认
- `运营中心管理`
  - 运营中心配置
  - 服务区域
  - 可履约商品
  - 库存维护

## 四、设计规范建议

### 1. 页面气质

- B 端业务系统风格，信息密度适中，不做营销化大图布局。
- 使用清晰的表格、状态标签、时间轴和抽屉详情。
- 页面主色建议使用稳重的蓝色或青色作为操作色，风险状态使用红/橙，成功状态使用绿。
- 不使用大面积装饰性渐变，不使用过多阴影和高饱和色块。

### 2. 布局规范

- 列表页：顶部筛选区 + 状态统计条 + 数据表格。
- 详情页：顶部摘要区 + 左侧主信息 + 右侧状态时间线。
- 审核页：左侧凭证预览 + 右侧审核信息和操作。
- 操作按钮固定在页面右上或底部操作栏，避免用户滚动后找不到。

### 3. 状态标签

| 状态类型 | 颜色建议 | 示例 |
| --- | --- | --- |
| 待处理 | 蓝色 | 待接单、待审核、待确认 |
| 进行中 | 青色 | 已接单、已发货、补货在途 |
| 成功完成 | 绿色 | 已签收、审核通过、已入库 |
| 警告 | 橙色 | 即将超时、凭证待补充 |
| 异常 | 红色 | 缺货、物流异常、凭证驳回 |
| 关闭 | 灰色 | 异常关闭、已取消 |

### 4. 表格规范

表格必须支持：

- 订单号复制。
- 状态筛选。
- 运营中心筛选。
- 时间范围筛选。
- 异常优先排序。
- 批量导出。
- 行内主操作不超过 2 个，其余进入更多菜单。

## 五、核心页面设计

### 1. 卓希后台：运营中心订单列表

#### 页面目标

帮助卓希订单运营快速判断当前运营中心履约订单的整体状态和待处理事项。

#### 顶部统计

- 全部运营中心订单
- 待运营中心确认
- 待发货
- 已发货待签收
- 凭证待审核
- 待生成补货
- 异常订单

#### 筛选项

- 订单状态
- 补货状态
- 运营中心
- 客户名称
- 商品/SKU
- 物流状态
- 是否异常
- 下单时间
- 发货时间
- 签收时间

#### 表格字段

| 字段 | 说明 |
| --- | --- |
| 运营中心订单号 | 主编号，支持复制 |
| 来源客户订单号 | 可点击跳转 |
| 客户名称 | 展示客户简称 |
| 运营中心 | 承接履约方 |
| 商品数量 | SKU 数量和总件数 |
| 接单状态 | 待确认、已确认、拒绝 |
| 发货状态 | 待发货、已发货、部分发货 |
| 签收/凭证 | 待签收、待审核、通过、驳回 |
| 补货状态 | 未生成、待确认、在途、完成 |
| 异常标记 | 缺货、超时、物流异常 |
| 操作 | 查看、催办、更多 |

#### 交互

- 点击订单号进入详情页。
- 点击异常标签打开异常说明抽屉。
- 点击催办弹出确认框，支持发送提醒并记录日志。
- 凭证待审核状态可直接进入审核页。

### 2. 卓希后台：运营中心订单详情

#### 页面结构

顶部摘要区：

- 运营中心订单号
- 当前状态
- 来源客户订单号
- 运营中心
- 客户名称
- 补货状态
- 异常标记

主体内容建议使用 Tab：

- 订单商品
- 物流信息
- 签收凭证
- 补货单
- 操作日志

右侧固定时间线：

1. 客户下单
2. 分配运营中心
3. 运营中心接单
4. 运营中心发货
5. 客户签收
6. 凭证审核
7. 补货单生成
8. 补货完成

#### 关键交互

- 在签收凭证 Tab 中可以审核通过或驳回。
- 在补货单 Tab 中可以查看已生成补货单，或在满足条件时生成补货单。
- 异常订单显示红色提示条，并提供处理入口。

### 3. 卓希后台：签收凭证审核页

#### 页面目标

让审核人员判断凭证是否足以触发补货。

#### 布局

- 左侧：凭证预览区，支持图片放大、旋转、切换附件。
- 右侧：订单摘要、商品发货数量、物流签收信息、审核操作。

#### 审核操作

- 审核通过
- 审核驳回
- 标记异常

驳回必须填写原因：

- 凭证不清晰
- 凭证信息不完整
- 数量不一致
- 未体现客户签收
- 其他

### 4. 卓希后台：补货单列表

#### 页面目标

帮助供应链管理所有待执行和执行中的补货单。

#### 顶部统计

- 待确认
- 待发货
- 补货在途
- 待入库确认
- 已完成
- 异常

#### 表格字段

| 字段 | 说明 |
| --- | --- |
| 补货单号 | 主编号 |
| 运营中心 | 补货接收方 |
| 来源订单数 | 关联运营中心订单数量 |
| 商品数量 | SKU 数和总件数 |
| 生成方式 | 自动/人工 |
| 补货状态 | 待确认、待发货、在途、完成 |
| 生成时间 | 系统生成时间 |
| 最近处理人 | 责任人 |
| 操作 | 查看、确认、发货 |

### 5. 卓希后台：补货单详情

#### 页面结构

- 补货单摘要
- 补货商品明细
- 来源运营中心订单
- 生成依据
- 补货物流
- 入库确认
- 操作日志

#### 设计重点

必须突出 `生成依据`：

- 来源客户订单
- 运营中心订单
- 签收凭证
- 实际发货数量
- 审核通过时间

这样供应链人员在确认补货前可以快速判断是否合理。

### 6. 运营中心端：工作台

#### 页面目标

让合作商人员一进入系统就看到自己需要处理什么。

#### 卡片/列表

- 待确认订单
- 待发货订单
- 已发货待签收
- 凭证被驳回
- 待确认入库补货单

#### 交互

- 点击待确认订单进入订单详情。
- 列表行支持快速接单。
- 待发货订单支持快速填写物流。
- 凭证驳回订单显示驳回原因。

### 7. 运营中心端：订单详情

#### 页面结构

- 订单摘要
- 收货信息
- 商品明细
- 发货信息
- 签收凭证
- 补货状态

#### 操作

- 确认接单
- 拒绝接单
- 填写物流
- 上传签收凭证
- 查看补货进度

拒绝接单必须选择原因：

- 库存不足
- 不在服务范围
- 商品异常
- 无法按时发货
- 其他

## 六、移动端适配建议

若运营中心人员主要通过手机处理，建议优先保障以下移动端体验：

- 工作台任务卡片优先展示待处理数量。
- 发货表单字段不超过一屏半。
- 物流单号支持扫码或粘贴。
- 凭证上传支持拍照。
- 审核驳回原因必须醒目展示。
- 按钮触控区域不小于 44px。

## 七、关键状态空页面

| 场景 | 空状态文案建议 |
| --- | --- |
| 暂无待接单 | 当前没有需要确认的运营中心订单 |
| 暂无待上传凭证 | 当前没有需要补充签收凭证的订单 |
| 暂无补货单 | 暂无待处理补货单 |
| 无筛选结果 | 没有符合条件的数据，请调整筛选条件 |

## 八、设计验收标准

- 列表页可以在 3 秒内识别当前最需要处理的订单状态。
- 详情页可以完整追溯客户订单、运营中心履约、物流、凭证、补货单。
- 审核人员无需离开审核页即可完成凭证查看和审核。
- 运营中心人员可以在一个详情页完成接单、发货、传凭证。
- 补货单详情必须展示清楚补货依据。
- 异常状态必须显著，且有明确下一步操作。
- 所有关键按钮文案使用业务动作，不使用模糊表达。
