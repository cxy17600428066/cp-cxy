卓希工厂订单正向履约需求文档

脱骨侠品牌 OMS V5 开发交付版 2026年11月3日

本 PRD 用于产品评审、研发实现及测试验收。覆盖订单新增、接单、延期协商、销售 H5 确认、正向履约、回执及配置；不包含售后与运输资料管理。数据权限按本人、下属及全局范围独立授权，所有入口执行同一套校验。

1 版本范围

包含模块核心目标
订单列表和新增复用订单卡片与明细，维护客户、商品、收货信息及结构化要求。
订单接单列表快速有货接单、标准按期或延期，按节点展示接单状态、责任人及时间。
销售确认 H5通过专属链接接受或调整工厂提出时间，反馈到工厂待办。
履约总览和重点客户展示各正向节点预计与实际时间，预警、超时及责任人。
回执管理上传及审核回执，按订单决定是否考核。
时效和权限配置商品、客户、节点及方案快照；角色操作权限与订单数据范围。

2 本次明确排除

不开发运输资料管理、售后、退款、退换货、售后审核和售后时效；协商流程不设置 OA 审批、领导审批或结果回传节点。不新增独立演示列表。约仓仅作为订单要求字段，独立约仓调度系统不在本 PRD 范围。

3 交付基准

业务规则以本 PRD 为准，V5 原型用于布局与交互走查。原型的固定日期、示例身份、浏览器缓存及历史演示分支不是生产实现；通知、跨设备同步、权限、事务和规则重算需要后端实现。待确认项见第九页，不以演示默认值代替业务决定。

4 角色和业务操作

角色允许操作默认数据范围
销售或业务员同一角色；查看本人订单；通过 H5 确认或调整交期。仅本人所属订单
销售领导查看下属订单及其履约进度；默认只读，不代下属确认。本人及组织树下属
全局查看角色查看全部订单、节点及汇总；不默认拥有编辑或导出能力。全局
工厂判断是否接单，提出延期；不能满足销售时间时提交协调。授权工厂业务范围
服务管理中心查看协调单，填写最终预估发货和到货时间及说明。授权协调业务范围
仓储物流及回执人员仅处理获授权的正向履约任务及对应资料。授权任务业务范围
权限管理员维护角色、组织关系、全局查看授权；授权操作留审计。配置权限不等于订单全局权限

接单方式

快速接单只能有货发货，不展示无货选项或无货时效，接口亦禁止无货快速接单。标准接单选择按期发货或申请延期；按期发货下不再二次选择有货或无货。

生效条件

工厂提交延期、销售回填和服务管理中心提交协调均不覆盖当前生效交期。只有工厂确认接单后才正式生效，保留原交期及各方建议时间。能查看订单不等于能处理该节点。

建议的业务访问隔离

工厂按授权工厂、服务管理中心按授权协调范围、仓储物流按已分配任务访问，采用独立业务范围授权；不得为方便处理而默认授予全局。具体工厂归属与任务分配字段由现有 OMS 主数据确认后落地。

5 接单状态机

编码与状态当前角色动作及下一状态
PENDING_FACTORY待工厂接单工厂快速有货或标准按期确认 → ACCEPTED；标准提交延期 → PENDING_SALES。
PENDING_SALES延期已提交 待销售确认销售接受工厂时间 → SALES_CONFIRMED；调整时间并填原因 → SALES_ADJUSTED。
SALES_CONFIRMED销售已确认 待工厂接单工厂可以履约 → ACCEPTED；不能履约，填工厂建议时间及原因 → PENDING_SERVICE。
SALES_ADJUSTED销售已调整 待工厂再确认工厂可以履约 → ACCEPTED；不能履约，填工厂建议时间及原因 → PENDING_SERVICE。
PENDING_SERVICE待服务管理中心协调服务管理中心填写最终预估发货、到货时间及说明 → PENDING_FINAL_FACTORY。
PENDING_FINAL_FACTORY协调结果已回填 待工厂确认工厂确认最终结果 → ACCEPTED；无法履约的退回路径需业务确认。
ACCEPTED已接单 履约中后续节点责任人记录实际接单事件，更新交期与计划，禁止重复接单。

列表和进度展示

原订单卡片保留商品、单价数量、金额、收货人、客户、时效类型、接单状态与操作栏。接单状态直接对应当前节点，不得把待销售、待协调统一写成待接单。展示当前责任人、销售回填时间和最终协调时间。状态筛选应支持每个节点，待接单大类可包含全部未接单节点，已接单仅包含 ACCEPTED。

提交延期前只显示申请表；提交后显示节点进度。预览节点不改变申请状态。销售确认无论接受还是调整，均须工厂再判断，不可直接跳到接单成功。通知销售是提交产生的事件，不设独立通知节点。

6 表单与销售确认 H5

表单字段和校验
延期申请原交期只读；延期自然小时大于0；工厂建议时间、原因必填；建议时间与时长联动。
销售接受使用后端保存的工厂建议时间，不信任 URL 或前端修改后的时间值。
销售调整建议时间、原因必填；去除空格后原因不得为空。保存成功转工厂再确认。
工厂不能接单工厂调整后建议时间及原因必填；保存双方时间，提交服务管理中心。
服务管理中心最终预估发货时间、最终预估到货时间、协调说明必填；到货不得早于发货。
最终确认显示原交期、销售反馈、工厂建议、最终双时间及说明；确认后原子更新状态与计划。

H5 页面

通过订单专属任务链接进入，展示订单号、真实客户、当前时间语义及工厂建议；提供确认与调整两种操作。系统客户主要协商到货时间，非系统客户按业务规则协商发货时间，字段不得混用。

链接绑定销售身份、订单、任务、当前版本和有效期；登录或可信身份认证后校验归属。链接转发不转移权限，领导的下属查看权或全局查看权不自动获得销售确认权。过期、无权限、已处理和版本更新分别提示，允许联系当前责任人或重新获取链接。

重复提交返回原结果，不重复推进流程。网络失败保留输入；成功展示提交时间、结果及下一责任人。生产环境通过服务端同步，不能依赖 localStorage。通知由后端发送和重试，不把复制链接视为通知已送达。

时间与记录

统一 Asia/Shanghai 时区，接口使用带偏移量的 ISO 8601。预计和实际完成分开保存；不以到达预计时间推断实际完成。多商品取适用规则中最长时效，订单创建时保存规则快照，配置变化不追溯覆盖旧订单。

7 数据权限模型

用户明确要求三类数据范围。建议按角色分配操作权限，按独立数据范围授权决定能看到哪些订单；后端统一求交，不由前端传入销售 ID 决定可见范围。

范围编码定义订单匹配规则
SELF 本人销售只看本人所属订单。order.ownerSalesId 等于当前登录用户 ID。创建人、联系人、客户销售文字字段不替代所属销售 ID。
TEAM 下属领导看本人及下属负责订单。本人 ID 加组织上下级关系的有效下属 ID 集合；默认包含各级下属，直属与全部下属可配置。
ALL 全局明确授予的角色可看全部订单。仅覆盖当前企业或租户内全部订单，禁止跨企业访问。
NONE 无授权未配置、授权失效或用户停用。默认拒绝；不能回退为全局。

组织与归属

销售层级来自统一组织或人员主数据，使用稳定用户 ID 与主管关系，不按姓名匹配。组织关系为空、循环或异常时拒绝扩大范围并提示管理员处理。下属调岗后按当前有效组织关系计算；订单的归属由当前 ownerSalesId 决定，历史操作角色和变更前归属保留在审计中。

订单创建时必须确定所属销售；来源订单由可信映射自动带入，无法确定则进入受限待分配队列，普通销售不可见。手工变更所属销售仅允许拥有归属调整权限的人员，记录原销售、新销售、原因、时间。原销售立即失去访问，新销售按范围获权；未处理销售任务重新校验或重新分配。

多角色合并

同一模块具有多个有效授权时，可见集合取并集；操作仍逐项判断角色权限、数据范围及任务责任人。例如 SELF 加 TEAM 得到本人及下属集合；ALL 只代表数据范围，不新增操作能力。离职、账号禁用或显式停用授权优先拒绝访问。

授权配置

管理员配置用户或角色、适用模块、SELF 或 TEAM 或 ALL、TEAM 层级方式、有效期及启用状态。ALL 仅由权限管理员授予和撤销，普通用户不能自选全局。授权变更应使服务端权限缓存立即失效，后续请求重新校验。

8 数据权限执行与接口

入口必须执行的约束
列表 搜索 状态数量后端查询先限定可见订单，再筛选、统计和分页；不可泄露不可见订单总数、搜索联想或客户提示。
详情 商品 附件 下载按订单归属验证权限，附件继承订单范围；不可因知道 ID 或下载 URL 绕过。
导出 批量操作导出权限独立授予；服务端按可见范围重新筛选。批量包含越权订单时默认整批拒绝，不静默处理部分数据。
总览 指标 预警 重点客户统计基于同一可见集合，领导及全局用户切换视角不改变操作权。
H5 任务 通知直达校验登录身份、任务归属、Token、数据范围、当前版本。只读链接不能调用处理接口。
变更及后台任务每次写入重新校验，异步导出执行时和下载时均复核权限，撤权后旧链接不能继续下载。

接口与后端控制建议

GET /orders 支持状态、日期、关键字及分页，数据范围由服务端推导。GET /orders/{id} 与附件接口复用订单鉴权。POST /orders/{id}/accept、/delay-requests 和延期单的 sales-decision、factory-decision、coordination、confirm 在事务内校验状态及版本。

新增角色授权、组织树查询、订单归属调整及审计查询接口。写请求使用幂等键和 version；版本冲突409、字段错误422、权限不足403。不可见或不存在的订单统一返回无权访问或不存在，不披露客户及金额。服务端日志保留具体拒绝原因。

9 订单字段与正向履约

订单要求字段规则
最新日期 当月日期分别记录是否要求最新生产日期、当月生产日期。最新日期的业务范围待确认，不自行设天数。
出厂及第三方检测两个独立布尔项，可同时需要；随货资料补充最多500字。
送货单与价格需要送货单为是才显示是否展示价格；切为否清空价格项，后端校验组合，不影响内部订单价格。
约仓 抽检 同一批次独立记录要求；不自动创建预约、质检或批次业务。
备注及草稿普通备注1024字、特殊备注500字；保存及重开恢复全部字段与联动。

配置及节点

商品时效、客户交期、标准快速方案及节点责任人应形成版本化快照。财务、接单、发货、揽收、签收及回执等节点按有效配置执行，预计和实际分离；节点完成由可信业务事件驱动。

回执管理

回执上传、审核、驳回后重新上传属于正向履约；不需回执的订单跳过相关考核，不能伪造已审核。

列表适配与状态

沿用原订单卡片，不增加平行演示列表。表头和内容列宽一致；长状态和责任人自然换行，时效类型完整展示，按钮不得被文本覆盖；窄 PC 窗口可横向滚动。H5 按390宽度适配，按钮触达区域至少44像素，加载、空、成功和失败均有明确反馈。

部分履约的时效状态规则

订单发生拆单且已有部分商品或数量完成履约、仍有应履约部分未完成时，原订单卡片的“时效状态”主标签显示“部分履约”。接单状态仍按原接单节点显示，两者互不替代。

场景时效状态主标签补充信息
部分已完成，剩余未到截止时间部分履约按商品行显示已完成/应完成、剩余数量及原截止时间，剩余部分继续计时。
部分已完成，剩余超过截止时间部分履约单独显示“剩余未完成部分已超时”和超时信息，不将主标签替换为正常、预警或已超时。
所有必需履约节点及数量全部完成退出部分履约状态按现有完成规则展示；完成节点实际时间取最后一批有效完成时间。

拆单不重置或延长时效。无已确认的批次新交期时沿用原节点截止时间；原订单权限、接单、延期协商及履约流程保持不变。预计完成不得作为实际完成，重复事件不重复累计数量。

待业务与研发评审确认

1 领导默认包含全部层级下属，本 PRD 按此设计；需确认组织主数据及跨部门兼管方式。2 工厂、服务管理中心和仓储人员的具体业务范围及分配来源。3 未归属订单的分配责任人。4 快速缺货异常处置及最终协调后仍不能接单的退回路径。5 最新日期定义、各确认节点SLA、通知渠道、H5链接有效期。上述事项不得自行演化为全局默认权限或 OA 审批。

开发交付约定

本 PRD 新增数据权限要求，原型尚未实现真实身份和后端行级权限。研发拆分权限、状态机、表单、H5、通知、节点计算与审计任务；测试按照上述数据范围和状态矩阵验收。正式上线前需完成接口联调、安全校验及业务评审。

补充需求 拆单后的部分履约与时效

当存在有效部分完成且仍有未完成数量时，订单的时效状态主标签统一显示“部分履约”，不再用正常、预警或超时覆盖该主标签。剩余未完成部分仍按原截止时间考核，并单独提示剩余超时；所有必需节点全部完成后不再显示部分履约。此补充沿用现有订单、接单、延期协商及正向履约节点，不新增接单状态、不重建审批或业务流程。只在原订单卡片、履约计划及现有详情中补充数量完成进度，沿用当前订单数据权限。

项目规则
节点完成各发货单保留原订单号、商品行标识、分配数量和实际节点事件。按商品行累计各批有效完成数量。0为未完成，大于0且小于应履约数量为部分完成，所有行全部达到才为整单该节点完成。
状态展示按当前节点显示部分发货、部分揽收、部分签收；不把首批发货认定全部发货。接单状态保持原状态机，履约完成程度是独立展示维度。
剩余时效已完成数量停止该节点考核；剩余数量继续按原节点截止时间计时，拆单不重置时效。缺少分配发货单的剩余数量仍需纳入监控。超时标记部分完成且剩余超时，不认定整单正常完成。
批次不同交期拆单不自动产生新交期。仅存在已确认生效的批次交期时按对应时间考核，保留原时间、调整原因和确认记录，不新建一套延期流程。
整单完成时间该节点全部数量有效完成后，取最后一批实际完成时间。全部签收后如仍有必需回执未完成，整单必需履约节点尚未全部完成；不扩大原配置考核范围。
数据校验不同商品与单位不直接相加，逐行显示已完成/应完成及剩余。重复事件幂等；分配数量不得超出应履约数量；撤销批次或回滚事件重新计算，保留记录。订单应履约数量调整沿用现有授权规则。

验收例：商品100件分60和40，60件已发货时显示部分发货60/100，40件继续按原截止计时；截止后40件未发显示剩余超时；40件完成后显示全部发货100/100，整单实际发货时间取最后一批。首批签收不代表整单签收。本人、下属、全局权限与原订单一致，不允许通过发货单绕过权限。

原型补充基于现有拆单发货记录展示节点数量进度；后端需在现有节点聚合器中落实剩余数量考核、撤销回算及幂等校验，不能仅依赖前端展示。未接入拆单记录时不伪造进度或完成时间。

延期各节点时间反馈展示

延期详情按原订单交期、工厂申请延期、销售确认、工厂再次确认、服务管理中心协调、工厂最终确认顺序展示。每行明确节点、反馈角色、本次建议或确认交期、反馈操作时间、处理结果及原因。承诺交期与提交时间分列；原始交期、首次工厂建议、销售反馈、工厂再次建议和最终双时间分别保存。未反馈显示待反馈，不使用后续时间补齐前序；最终确认前明确当前生效时间，确认后展示最终生效时间。

服务管理中心协调附件

协调说明下新增选填附件上传，支持PNG、JPG、PDF，最多3个，每个不超过2MB。支持移除、下载并随协调结果保存，工厂最终确认时可查看。附件继承订单数据权限，生产实现由文件服务校验内容类型、大小和访问权限；失败保留表单。原型本地合计限制3MB，不作为服务端存储方案。

分享销售确认链接

待销售确认环节在打开链接旁提供分享确认链接按钮，复制当前订单和任务专属H5地址；复制成功给予反馈，剪贴板不可用时展示只读链接供手动复制。链接分享不授予访问权限，仍校验当前销售身份与订单归属；本机原型链接需部署后才能跨设备访问。

各履约方案独立配置计时方式

计时规则必须跟随履约方案，在方案编辑页的节点时限中配置，不存在独立全局配置。同一方案内各系统客户倒排节点可分别选择固定小时或时间比例，同一节点仅一种生效。每条方案规则独立保存 timingMode（hours或ratio）、leadHours、leadRatio、minimumHours 和原有预警及责任配置；复制方案时复制规则，编辑副本不影响原方案。固定小时为要求到货前预留小时；比例为从订单提交至要求到货的总可用时长的预留比例。签收截止即要求到货时间。最低必要时长仅作冲突校验，不静默覆盖比例结果。下单时已早于截止时间视为交期冲突，非工厂已超时；由工厂确认加急或申请延期。节点截止顺序校验、订单快照、拆单沿用原截止及延期确认后版本化重算均需后端实现。原型支持方案内模式切换与保存，时效预测读取所选已保存方案规则，输入提交及到货时间进行试算；不同方案相互隔离，既有历史订单不自动改算。原固定小时方案默认仍为固定小时，之前误设的全局计时字段不作为任何方案的生效来源。

方案配置交互展示

方案编辑页使用逐节点卡片，固定小时与时间比例采用可直接点击的互斥选项，配置值带明确单位及自然语言计算说明。预警和责任人置于卡片可展开区域。右侧本方案时间轴提供订单提交、到货时间及2天/5天示例切换，输入后实时计算节点截止、最低时长与顺序冲突。未保存编辑仅作用于当前预览；保存后归属本方案，其他方案不受影响。
