3. 接单和延期状态机（开发基准）

快速接单只支持有货发货；不显示无货选项、无货时效或无货提交分支。标准接单只选择按期发货或申请延期，不在按期发货下二次选择有货 / 无货。

状态编码 / 列表文案责任人允许动作与转移
PENDING_FACTORY / 待工厂接单工厂快速：确认有货 → ACCEPTED。标准：按期确认 → ACCEPTED；提交延期表单 → PENDING_SALES。
PENDING_SALES / 延期已提交，待销售确认销售H5 接受工厂时间 → SALES_CONFIRMED；H5 调整时间并说明原因 → SALES_ADJUSTED。接受时间不直接接单。
SALES_CONFIRMED / 销售已确认，待工厂接单工厂可以接单 → ACCEPTED；不能接单，填写建议时间和原因 → PENDING_SERVICE。
SALES_ADJUSTED / 销售已调整，待工厂再次确认工厂同上，两种销售反馈均必须由工厂判断，不得自动同意。
PENDING_SERVICE / 待服务管理中心协调服务管理中心填写最终预估发货、到货时间及说明 → PENDING_FINAL_FACTORY。
PENDING_FINAL_FACTORY / 协调结果已回填，待工厂确认工厂确认 → ACCEPTED，正式生效。最终确认无法履约的退回规则尚需产品确认，不应静默强制通过。
ACCEPTED / 已接单，履约中下一履约节点责任人记录实际接单时间，生效交期与履约计划；接单操作不可重复执行。

不设置“通知业务员”独立节点，不设置 OA 审批、领导审批或结果回传节点。链接通知属于提交动作产生的通知事件，不是流程状态。销售直接接受时，可跳过服务管理中心，但仍须工厂确认。

4. 延期表单和时间规则

  • 延期时长为正数自然小时；调整后时间、原因必填。后端保存原交期、工厂建议、销售反馈、服务管理中心最终时间和最终生效时间，禁止互相覆盖。
  • 系统客户主要协商到货时间；非系统客户按指定业务规则协商发货时间。界面必须标明时间语义，不得把发货时间写入到货字段。
  • 服务管理中心同时填写最终预估发货时间与预估到货时间，到货不得早于发货。无法接单原因去除空格后非空。
  • 申请、销售确认、协调提交阶段不修改当前生效交期。工厂最后确认后事务性保存新交期、接单事件、状态与计划快照；保留旧版本及记录。
  • 延期时长和新交期应联动计算，避免两者不一致；生产环境基准时间来自订单，不能使用原型固定日期。时区统一 Asia/Shanghai，接口使用带偏移量的 ISO 8601。
  • 履约节点按快照规则推算；并行节点按既定规则处理，多商品按匹配规则中最长时效。预计时间与实际完成时间分别存储。

6. H5 链接与安全

  • 展示订单号、客户、工厂建议时间、时间类型、调整原因、当前处理状态。客户名称与建议时间必须来自订单接口，不使用原型固定客户。
  • 链接形式建议 /sales-confirmation/{taskToken}；Token 绑定订单、销售身份、当前版本、有效期、动作范围。不得仅依靠 URL 订单号授权。
  • 销售登录或可信身份校验；无权限、过期、已处理、订单版本更新分别展示原因及恢复入口。刷新已提交链接展示提交结果，不重复提交。
  • 接受：使用后端保存的工厂建议时间。调整：新时间与原因必填。保存失败保留输入。后端验证状态和权限，幂等写入审计，再返回工厂待办。
  • 消息发送、重试、去重由服务端负责；仅“复制链接”不是通知成功。通知渠道需项目接入方确认。

  8. 字段送货单价格联动正确，草稿恢复正确；内部商品价格不受随货单价格展示要求影响。
  9. 回执需求关闭时跳过对应节点，不伪造审核完成；实际发货等事件不得由预计时间推断。
  10. 本版菜单无售后入口，交付包不包含售后模块文件，不开发售后状态、接口及通知。

补充需求 拆单后的部分履约与时效

当存在有效部分完成且仍有未完成数量时，订单的时效状态主标签统一显示“部分履约”，不再用正常、预警或超时覆盖该主标签。剩余未完成部分仍按原截止时间考核，并单独提示剩余超时；所有必需节点全部完成后不再显示部分履约。此补充沿用现有订单、接单、延期协商及正向履约节点，不新增接单状态、不重建审批或业务流程。只在原订单卡片、履约计划及现有详情中补充数量完成进度，沿用当前订单数据权限。

项目规则
节点完成各发货单保留原订单号、商品行标识、分配数量和实际节点事件。按商品行累计各批有效完成数量。0为未完成，大于0且小于应履约数量为部分完成，所有行全部达到才为整单该节点完成。
状态展示按当前节点显示部分发货、部分揽收、部分签收；不把首批发货认定全部发货。接单状态保持原状态机，履约完成程度是独立展示维度。
剩余时效已完成数量停止该节点考核；剩余数量继续按原节点截止时间计时，拆单不重置时效。缺少分配发货单的剩余数量仍需纳入监控。超时标记部分完成且剩余超时，不认定整单正常完成。
批次不同交期拆单不自动产生新交期。仅存在已确认生效的批次交期时按对应时间考核，保留原时间、调整原因和确认记录，不新建一套延期流程。
整单完成时间该节点全部数量有效完成后，取最后一批实际完成时间。全部签收后如仍有必需回执未完成，整单必需履约节点尚未全部完成；不扩大原配置考核范围。
数据校验不同商品与单位不直接相加，逐行显示已完成/应完成及剩余。重复事件幂等；分配数量不得超出应履约数量；撤销批次或回滚事件重新计算，保留记录。订单应履约数量调整沿用现有授权规则。

验收例：商品100件分60和40，60件已发货时显示部分发货60/100，40件继续按原截止计时；截止后40件未发显示剩余超时；40件完成后显示全部发货100/100，整单实际发货时间取最后一批。首批签收不代表整单签收。本人、下属、全局权限与原订单一致，不允许通过发货单绕过权限。

原型补充基于现有拆单发货记录展示节点数量进度；后端需在现有节点聚合器中落实剩余数量考核、撤销回算及幂等校验，不能仅依赖前端展示。未接入拆单记录时不伪造进度或完成时间。

延期各节点时间反馈展示

延期详情按原订单交期、工厂申请延期、销售确认、工厂再次确认、服务管理中心协调、工厂最终确认顺序展示。每行明确节点、反馈角色、本次建议或确认交期、反馈操作时间、处理结果及原因。承诺交期与提交时间分列；原始交期、首次工厂建议、销售反馈、工厂再次建议和最终双时间分别保存。未反馈显示待反馈，不使用后续时间补齐前序；最终确认前明确当前生效时间，确认后展示最终生效时间。

协调说明下新增选填附件上传，支持PNG、JPG、PDF，最多3个，每个不超过2MB。支持移除、下载并随协调结果保存，工厂最终确认时可查看。附件继承订单数据权限，生产实现由文件服务校验内容类型、大小和访问权限；失败保留表单。原型本地合计限制3MB，不作为服务端存储方案。

各履约方案独立配置计时方式

计时规则必须跟随履约方案，在方案编辑页的节点时限中配置，不存在独立全局配置。同一方案内各系统客户倒排节点可分别选择固定小时或时间比例，同一节点仅一种生效。每条方案规则独立保存 timingMode（hours或ratio）、leadHours、leadRatio、minimumHours 和原有预警及责任配置；复制方案时复制规则，编辑副本不影响原方案。固定小时为要求到货前预留小时；比例为从订单提交至要求到货的总可用时长的预留比例。签收截止即要求到货时间。最少需要时间仅作冲突校验，不静默覆盖比例结果。下单时已早于截止时间视为交期冲突，非工厂已超时；由工厂确认加急或申请延期。节点截止顺序校验、订单快照、拆单沿用原截止及延期确认后版本化重算均需后端实现。原型支持方案内模式切换与保存，时效预测读取所选已保存方案规则，输入提交及到货时间进行试算；不同方案相互隔离，既有历史订单不自动改算。原固定小时方案默认仍为固定小时，之前误设的全局计时字段不作为任何方案的生效来源。

方案配置交互展示

方案编辑页使用统一节点配置总表，每行一个履约节点，列包括启用监控、节点、计时基准、固定小时或比例方式、时限及单位、最少需要时间、预警、责任角色及试算截止。所有必要配置直接展开，便于逐行对比。表格上方设置提交和到货时间，支持2天/5天切换，计算结果在各节点同一行实时展示，冲突单独提示。未保存编辑仅作用于当前预览；保存后归属本方案，其他方案不受影响。

计时字段名称及悬浮说明

节点配置中的“最少需要时间”指本节点完成至要求到货之间，后续环节至少需要的小时数，仅作交期风险校验；填0不增加该项校验。“截止前提醒”指接近节点截止时间时的提醒阈值；非系统客户仍按已用时比例设置。字段名旁提供说明图标，鼠标移入、键盘聚焦或点击可阅读，Escape可关闭点击展开状态。

全部客户方案的计时基准展示

当方案适用全部客户时，每个节点的计时基准按系统客户与非系统客户分别展示。系统客户适用倒排的节点标明要求到货前倒排；非系统客户标明具体起算事件，例如工厂接单后、WMS收到订单后、WMS出库后。回执等正向节点两类客户均展示实际事件起算，不因共用方案混为倒排。
