# 全费用管理交互原型

## 客户活动策略整合

整合用户提供的 `C:/Users/admin/Documents/New project/dealer-strategies.html`，原文件保持不变，参考副本位于 `99-附件与参考/客户活动策略-整合参考.html`。原型采用同一客户和同一账本，不使用 iframe 或另建余额。

业务层级为：客户 → 商业政策版本 → 客户活动方案 → 19 类策略快照 → 费用试算与方案审批 → 执行单据 → 预算审批、核销、结算清偿 → 客户贡献与受益台账。客户及商业政策详情均增加业务关联入口；侧栏“客户活动策略”提供方案列表和策略库。

19 类业务为：采购返利、进货折扣、回款奖励、动销奖励、市场补贴、满额减免、买赠满赠、组合采购优惠、采购增长奖励、连续采购奖励、年度目标奖励、运费补贴、新品试销支持、库存价保调换、陈列奖励、经销商推荐奖励、沉默激活、合同扣点、年返。每项保留源规则、结构化参数、独立测算输入、税口径与执行阶段，并可内嵌到活动方案。

已生效方案保存修改为候选版本，中心池负责人、财务及业务复核全部通过后替换执行版本；原版、策略快照及审批记录保留。方案本身不注入预算，市场费用执行仍由原组织池授权；额度上限同时校验方案和实际账户。规则库更新不回改历史方案，已保存试算保留引用方案版本。

边界：组合报价仅对折扣、满减、激活减免、运费执行单笔顺序叠加或择优，其余业务使用各自输入和期间独立测算，不将所有奖励相加当作应付。跨方案命中、历史已领、客户资质、库存和真实 OA 未自动核验。价格经 OMS 成交价承接；返利走客户预留；实物需库存成本及凭证；合同扣点独立处理。当前自动串联的执行链为市场费用申请、审批占用、核销释放与清偿；其余类型提供规则与对应业务入口，不冒充已完成真实交付。

实现源文件为 `dealer-catalog.js`、`dealer-integration.js`，统一由 `pack_schemes.py` 嵌入 HTML。`qa_dealer.mjs` 验证规则覆盖、快照、方案变更审批和市场执行链。

## 客户费用总台账列表

入口先展示客户列表，支持名称或编码搜索、中心、业务模式及台账状态筛选。点击客户进入独立台账，返回保留筛选，地址可刷新恢复。客户 A 保留原有演示账本；其他客户只有政策和试算数据，未导入的销售、贡献和余额以 — 显示。已核销跨客户活动按受益客户展示来源和确认金额，不生成受益方新余额。实现源文件 `customer-ledger.js`，验收脚本 `qa_customer_ledger.mjs`。

## 独立页面交互更新

政策查看、新建、编辑及复制，试算打开、新建及复制，活动申请、明细审核和核销均采用独立业务页，进入后替换主内容区，不在列表下方叠加。顶部提供返回及层级路径；列表筛选和滚动位置保留。试算及政策保存成功返回原列表，校验失败保留当前输入。未保存离开需确认，浏览器前后退和已保存详情刷新通过 hash 地址恢复。清偿登记、重置和放弃更改等轻量操作保留弹窗。验收脚本为 `qa_navigation.mjs`；路由实现源文件 `page-navigation.js` 随 `pack_schemes.py` 嵌入 HTML。

## 客户方案列表更新 2026年11月16日

本轮依据用户圈定的“客户政策”和“销售费用试算”入口调整：先呈现方案列表，再新建或打开具体方案。沿用原型风格和现有目录，新增客户独立配置、政策版本及试算快照；目标是可为不同客户分别配置参数并复现测算，成功标准为切换客户不串用政策、保存后可恢复相同结果、已生效政策与原账本不被覆盖。本轮不变更财务清偿或活动规则，不承诺生产发布。

政策方案覆盖经销、托盘、餐饮直供和私域四个演示客户。已生效方案只读，调整时复制为新版本草稿。试算列表支持新建、复制、打开及保存；草稿政策可以试算，但不是批准计提依据。规则 Word 仍为原规则建议稿，新增页面设计见 `05-产品方案/02-信息架构.md`。
