# 全费用管理交互原型

## 客户费用总台账列表

入口先展示客户列表，支持名称或编码搜索、中心、业务模式及台账状态筛选。点击客户进入独立台账，返回保留筛选，地址可刷新恢复。客户 A 保留原有演示账本；其他客户只有政策和试算数据，未导入的销售、贡献和余额以 — 显示。已核销跨客户活动按受益客户展示来源和确认金额，不生成受益方新余额。实现源文件 `customer-ledger.js`，验收脚本 `qa_customer_ledger.mjs`。

## 独立页面交互更新

政策查看、新建、编辑及复制，试算打开、新建及复制，活动申请、明细审核和核销均采用独立业务页，进入后替换主内容区，不在列表下方叠加。顶部提供返回及层级路径；列表筛选和滚动位置保留。试算及政策保存成功返回原列表，校验失败保留当前输入。未保存离开需确认，浏览器前后退和已保存详情刷新通过 hash 地址恢复。清偿登记、重置和放弃更改等轻量操作保留弹窗。验收脚本为 `qa_navigation.mjs`；路由实现源文件 `page-navigation.js` 随 `pack_schemes.py` 嵌入 HTML。

## 客户方案列表更新 2026年11月16日

本轮依据用户圈定的“客户政策”和“销售费用试算”入口调整：先呈现方案列表，再新建或打开具体方案。沿用原型风格和现有目录，新增客户独立配置、政策版本及试算快照；目标是可为不同客户分别配置参数并复现测算，成功标准为切换客户不串用政策、保存后可恢复相同结果、已生效政策与原账本不被覆盖。本轮不变更财务清偿或活动规则，不承诺生产发布。

政策方案覆盖经销、托盘、餐饮直供和私域四个演示客户。已生效方案只读，调整时复制为新版本草稿。试算列表支持新建、复制、打开及保存；草稿政策可以试算，但不是批准计提依据。规则 Word 仍为原规则建议稿，新增页面设计见 `05-产品方案/02-信息架构.md`。

`customer-schemes.js` 是方案功能源文件，修改后运行 `pack_schemes.py` 嵌入单文件 HTML。无需复制此 JS 才能打开原型。

- 原型入口：[原型.html](./原型.html)，可直接用浏览器打开，无需启动服务。
- 规则文档：[全费用管理规则建议稿 V1](../../05-产品方案/脱骨侠全费用管理规则建议稿V1.docx)。
- `rules.json` 为规则数据，`build_deliverables.py` 为生成脚本，Word 输出至工作区 `05-产品方案`。
- `qa/` 保留排版预览与浏览器检查结果；`qa.mjs`、`qa_multipoool.mjs` 为演示流程验收脚本。
- `render_word.ps1` 使用本机 Word 导出内部排版预览。

原型包含客户台账、政策草稿、销售费用试算、组织费用池、活动与核销、审核工作台、结算清偿、异常对账和规则说明。所有数据与角色均为演示，不连接真实业务系统。

按工作区既有分类归档：规则设计文档放在 `05-产品方案`，交互原型及其配套资源放在 `09-设计与原型`。
