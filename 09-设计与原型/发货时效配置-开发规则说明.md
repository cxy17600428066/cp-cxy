# 发货时效配置——开发规则说明

## 1. 目的

本功能用于统一计算商品从订单生效、发货、物流揽收到客户签收各阶段的履约时间。

系统支持两级配置：

1. 商品已关联发货方案：使用商品关联的方案。
2. 商品未关联发货方案：使用全局规则。

方案发布后只影响新生成的履约单。已经生成的履约单必须保存规则快照，不得因后台修改方案而改变原承诺时间。

---

## 2. 统一时间口径

### 2.1 订单生效时间 `order_effective_at`

所有发货阶段时效均从订单生效时间开始计算。

- 在线支付订单：支付成功时间。
- 账期、授信或货到付款订单：订单审核通过时间。
- 人工创建订单：订单提交成功且进入“待履约”状态的时间。
- 支付后还需要人工审核的订单：以审核通过时间为准。

未支付、审核驳回或已取消订单不开始计时。

### 2.2 时间单位

- 后台配置单位：小时。
- 数据库存储单位：建议使用分钟或秒，避免小数小时。
- 默认按照自然时间连续计算，包括周末和节假日。
- 服务端统一保存 UTC 时间，页面按照 `Asia/Shanghai` 展示。
- 如果以后需要排除节假日，应增加“工作日历”能力，不建议在本期代码中写死。

### 2.3 规则快照

订单生效时需要保存：

- 命中的方案 ID、方案名称和方案版本。
- 库存状态：有货或没货。
- 六个时效配置值。
- 各阶段计算出的截止时间。

后台修改或删除方案不得反向修改历史订单快照。

---

## 3. 六个时效的定义与计算

## 3.1 有货发货时效

### 定义

订单生效时商品可用库存充足，商家承诺完成发货的最长时间。

### 有货判断

```text
可用库存 = 实际库存 - 已锁定库存 - 不可售库存

如果：可用库存 >= 本次履约数量
则：库存状态 = 有货
```

库存状态在订单生效时生成快照。后续库存增加或减少，不重新改变该订单命中的时效类型。

### 计算公式

```text
有货发货截止时间 = 订单生效时间 + 有货发货时效
```

### 示例

```text
订单生效时间：2026-08-06 10:00
有货发货时效：24 小时
有货发货截止时间：2026-08-07 10:00
```

---

## 3.2 没货发货时效

### 定义

订单生效时商品可用库存不足，需要采购、生产、调拨或补货时，商家承诺完成发货的最长时间。

### 没货判断

```text
如果：可用库存 < 本次履约数量
则：库存状态 = 没货
```

如果库存只能满足部分数量，建议拆成有货履约单和缺货履约单，分别计算；如果本期系统不支持拆分，则整条商品按“没货”处理。

### 计算公式

```text
没货发货截止时间 = 订单生效时间 + 没货发货时效
```

### 示例

```text
订单生效时间：2026-08-06 10:00
没货发货时效：72 小时
没货发货截止时间：2026-08-09 10:00
```

---

## 3.3 预计发货时效

### 定义

用于订单详情、客服工作台或客户侧展示的预计发货时间，是业务预计值，不直接用于判定发货超时。

### 计算公式

```text
预计发货时间 = 订单生效时间 + 预计发货时效
```

为了避免预计时间晚于承诺发货时间，最终展示值建议采用：

```text
展示预计发货时间 = min（预计发货时间，命中的发货截止时间）
```

其中“命中的发货截止时间”根据订单生效时的库存状态，选择有货发货截止时间或没货发货截止时间。

### 示例

```text
订单生效时间：2026-08-06 10:00
预计发货时效：24 小时
预计发货时间：2026-08-07 10:00
```

### 注意

预计发货时间只是展示和排期时间。是否超时必须根据“发货截止时间”和“发货超时时间”判断。

---

## 3.4 发货超时时效

### 定义

订单生效后，超过该时间仍未完成发货，则将履约单标记为“发货超时”。可用于预警、催办、绩效或处罚。

### 计算公式

```text
发货超时时间 = 订单生效时间 + 发货超时时效
```

### 超时判断

```text
当前时间 >= 发货超时时间
并且 shipped_at 为空
则：发货状态 = 已超时
```

建议在到期前增加预警：

```text
发货预警时间 = 发货超时时间 - 预警提前量
```

预警提前量可默认设置为 12 小时，也可以后续单独配置。

### 配置校验

```text
发货超时时效 >= 预计发货时效
发货超时时效 >= 有货发货时效
发货超时时效 >= 没货发货时效
```

---

## 3.5 揽收时效

### 定义

商家完成发货并生成有效物流单号后，物流公司产生首次有效揽收轨迹的最长时间。

“已发货”和“已揽收”必须区分：录入物流单号不代表物流公司已经取走商品。

### 起算时间

```text
shipped_at = 发货单完成出库，并成功生成或绑定物流单号的时间
```

### 计算公式

```text
最晚揽收时间 = shipped_at + 揽收时效
实际揽收耗时 = first_pickup_at - shipped_at
```

### 超时判断

```text
当前时间 >= 最晚揽收时间
并且 first_pickup_at 为空
则：揽收状态 = 已超时
```

### 有效揽收轨迹

应以物流接口返回的标准“已揽收”节点为准。仅有“电子面单已创建”“物流信息已收到”等预录入轨迹，不能视为已揽收。

---

## 3.6 签收时效

### 定义

物流公司首次有效揽收后，到客户完成签收允许的最长运输时间。

### 起算时间

以物流接口返回的首次有效揽收时间 `first_pickup_at` 为准，不以商家发货时间起算。

### 计算公式

```text
最晚签收时间 = first_pickup_at + 签收时效
实际签收耗时 = signed_at - first_pickup_at
```

### 超时判断

```text
当前时间 >= 最晚签收时间
并且 signed_at 为空
并且物流单未关闭、未退回
则：签收状态 = 已超时
```

### 示例

```text
首次揽收时间：2026-08-07 18:00
签收时效：72 小时
最晚签收时间：2026-08-10 18:00
```

拒收、退回、物流关闭不能记录为正常签收，应进入物流异常或售后流程。

---

## 4. 完整时间轴

```text
订单生效
  │
  ├─ 判断库存状态，命中有货或没货发货时效
  ├─ 计算预计发货时间
  ├─ 计算发货截止时间和发货超时时间
  │
商家发货 shipped_at
  │
  ├─ 计算最晚揽收时间
  │
物流首次揽收 first_pickup_at
  │
  ├─ 计算最晚签收时间
  │
客户签收 signed_at
```

---

## 5. 方案命中与混合订单

### 5.1 方案优先级

```text
商品关联方案 > 全局规则
```

一个商品同一时间只能关联一个已启用方案。

### 5.2 混合订单

同一订单包含不同方案商品时，不应使用整单统一时效。系统应按照“方案 + 仓库 + 发货批次”拆分履约单，每个履约单分别计算时效。

例如：

```text
商品 A：现货鸡爪方案，24 小时内发货
商品 B：预制鸡爪方案，72 小时内发货

结果：生成两个履约单，分别计算发货截止时间。
```

订单级状态由履约单汇总：

- 全部履约单已发货：订单已发货。
- 部分履约单已发货：订单部分发货。
- 任一未发货履约单超时：订单存在发货超时。

---

## 6. 拆单和多包裹规则

时效应优先按照履约单或包裹计算，不建议直接按照整个订单计算。

- 发货完成：包裹完成出库并绑定有效物流单号。
- 揽收完成：该包裹产生首次有效揽收轨迹。
- 签收完成：该包裹产生正常签收轨迹。
- 一个履约单有多个包裹时，全部包裹完成才算该履约单完成对应阶段。
- 订单级实际完成时间取最后一个包裹完成该阶段的时间。

---

## 7. 暂停和终止计时

### 终止计时

以下情况终止未完成阶段的计时：

- 订单取消。
- 履约单关闭。
- 商品全额退款且不再发货。

### 不建议自动暂停

以下情况默认不暂停计时：

- 等待补货。
- 仓库缺货。
- 商家未及时处理。
- 物流尚未上门。

这些属于履约过程，应正常计算超时。

如果因客户原因需要暂停，应建立独立的“客户原因暂停”记录，保存暂停开始、结束时间和原因，截止时间顺延暂停时长，并保留操作日志。

## 8. 建议数据字段

### 8.1 方案表 `shipping_time_scheme`

| 字段 | 说明 |
|---|---|
| `id` | 方案 ID |
| `name` | 方案名称 |
| `in_stock_ship_minutes` | 有货发货时效 |
| `out_stock_ship_minutes` | 没货发货时效 |
| `estimated_ship_minutes` | 预计发货时效 |
| `ship_timeout_minutes` | 发货超时时效 |
| `pickup_minutes` | 揽收时效 |
| `sign_minutes` | 签收时效 |
| `status` | 草稿、已启用、已停用 |
| `version` | 方案版本 |

### 8.2 履约单快照字段

| 字段 | 说明 |
|---|---|
| `order_effective_at` | 订单生效时间 |
| `stock_status_snapshot` | 有货或没货 |
| `scheme_id_snapshot` | 命中的方案 ID |
| `scheme_version_snapshot` | 命中的方案版本 |
| `estimated_ship_at` | 预计发货时间 |
| `ship_deadline_at` | 有货或没货发货截止时间 |
| `ship_timeout_at` | 发货超时时间 |
| `shipped_at` | 实际发货时间 |
| `pickup_deadline_at` | 最晚揽收时间 |
| `first_pickup_at` | 实际首次揽收时间 |
| `sign_deadline_at` | 最晚签收时间 |
| `signed_at` | 实际签收时间 |

建议同时保存六个时效分钟数快照，方便审计和问题追溯。

---

## 9. 状态判断伪代码

```text
订单生效时：
  rule = 商品关联方案 ?? 全局规则
  stock_status = 根据可用库存生成快照

  if stock_status == 有货：
      ship_deadline_at = order_effective_at + rule.in_stock_ship_minutes
  else：
      ship_deadline_at = order_effective_at + rule.out_stock_ship_minutes

  estimated_ship_at = min(
      order_effective_at + rule.estimated_ship_minutes,
      ship_deadline_at
  )

  ship_timeout_at = order_effective_at + rule.ship_timeout_minutes

发货时：
  shipped_at = 当前时间
  pickup_deadline_at = shipped_at + rule.pickup_minutes

首次揽收时：
  first_pickup_at = 物流轨迹中的首次有效揽收时间
  sign_deadline_at = first_pickup_at + rule.sign_minutes

签收时：
  signed_at = 物流轨迹中的正常签收时间
```

## 10. 开发验收示例

配置：

```text
有货发货：24 小时
没货发货：72 小时
预计发货：24 小时
发货超时：96 小时
揽收时效：12 小时
签收时效：72 小时
```

有货订单：

```text
订单生效：8 月 6 日 10:00
预计发货：8 月 7 日 10:00
发货截止：8 月 7 日 10:00
发货超时：8 月 10 日 10:00
实际发货：8 月 7 日 08:00
最晚揽收：8 月 7 日 20:00
实际揽收：8 月 7 日 18:00
最晚签收：8 月 10 日 18:00
```

上述时间应在订单详情、履约单详情和超时任务中保持一致。
