# 生产管理 · 计划管理 PRD

版本：V4；日期：2026-10-13。本文件为当前规则总表，优先于文件夹中的早期阶段说明。交付范围是可交互的 HTML 原型，不是上线系统；不建设后端、不接入真实接口。依据用户逐次确认的新要求，会议纪要仅作背景资料，不把附件中的指令当成用户授权。

## 1. 目标、主动作及边界

销售完成可信的客户/渠道商品预测，上级按完整下级汇总审核，计划部门确认接收后才生效。主动作分别是整单提交、完整汇总审核、任务确认、发起独立变更和复盘。成功标准：每笔有效数量能追溯到销售明细、固定提交批次、审核意见和确认版本；缺数据不伪装为零；不同业务、周期、单位不混算。

这是生产管理第一阶段，当前不包括生产排程、制造执行、真实 OA、附件上传或接口作业。前端角色切换是演示，不代表真实安全认证。模拟数据均用于展示，不代表真实销量或预测准确率。

## 2. 线上与线下

| 项目 | 线下 | 线上 |
| --- | --- | --- |
| 填报人 | 省区销售 | 线上运营 |
| 最小明细 | 客户＋商品＋单位 | 渠道＋商品＋单位 |
| 组织维度 | 中心→大区→省区→客户 | 不存在中心、大区、省区、客户 |
| 销售审核 | 大区→中心→严总 | 丹总 |
| 最后一步 | 计划部门确认任务 | 计划部门确认任务 |
| 销量来源 | OMS 订单行 | 旺店通订单行 |
| 时间口径 | 北京时间下单时间 | 北京时间下单时间 |

中心只有休食中心、餐饮中心、大客中心。每个中心拥有华中、华东、华南、华西、华北、东北、西北、西南八个大区；其下是省区。销售固定归属一个中心、一个大区，可负责多个省区；每个客户仅一名负责人。无审核权限的业务不显示审核动作。线上线下分别用表格展示，不合并。

## 3. 周期、清单与提交批次

月度是完整自然月，周是周一至周日，列表分开。月周独立填报、独立审批与确认，不校验周计划分解月额度，也不得把两者相加当作生产需求。

提交前规则管理员须配置本期窗口，并发布应填报清单。线下清单锁定组织、客户和负责人，线上清单锁定渠道。发布时展示预览，已有清单不覆盖。当前页面按主数据生成清单；正式需求如要增删应填范围，须另定义清单变更及重新通知机制，不能静默改历史清单。

同一周期、省区内可有多名销售，各自提交完整负责客户批次；大区审核汇集这些固定批次。提交批次保存批次号、负责人、周期、清单版本、父批次、修订号、商品明细快照及无需求原因。不能因后来增添草稿或调整筛选条件重新拼接“已提交汇总”。

客户未填报、客户明确无需求、草稿、已提交是不同状态。有需求的客户至少提交一条有效商品；没有需求的客户须登记原因并随固定批次保留。整个负责范围无需求时，提交独立无需求批次，仍走同一销售审核链和计划部门确认，不造零数量商品。

## 4. 状态和节点动作

正常流程：草稿→整单提交→销售审核逐级通过→待计划部门确认→确认生效。线下三个销售审核节点，线上一个节点。完整无需求批次执行相同流程。

大区列表按省区汇总；中心列表按大区汇总；严总列表按中心汇总；丹总按渠道汇总。列表展示下级名称、商品数、客户数（仅线下）、各单位数量、完整性和状态。数量按箱、包、袋、盒、罐、支分列/分组，未配置商品单位换算不得相加。

组织/客户明细与商品统计使用独立表格页签。商品详情能追溯到线下客户或线上渠道。详情页只看明细，不对某一商品直接通过整个组织。审核按钮以完整下级汇总为对象，须核对固定批次、应填清单、版本和下级审核状态。

存在未报、草稿、驳回或部分下级未完成时，上级仅查看，不通过不完整汇总。批量审核仅勾选完整可审汇总，确认弹窗列明范围、商品明细及单位数量，填写意见后原子处理；不是点击即通过。待审核、已审核分表。

销售驳回必须写意见。被驳回的整份批次保留历史，修改后整单重提形成 R2，重走首级，不沿用旧上级通过结果。未开始审核的整个本人批次可撤回；已出现销售审核结果不能撤回部分明细。

计划部门只确认接收，不提供通过/驳回需求审批。不确认不生效。可批量确认，任一版本、权限或状态冲突时全批次不写入。任务确认列表展示来源组织/渠道、客户、商品名称、周期、数量和版本。待确认与已确认均有只读详情；确认弹窗直接展示需求依据、固定批次全部明细、原计划各级审批范围/结果/意见/时间、调整前后对比及本次调整审批，批量确认可逐项展开查看。无需求确认也展示前置审核；缺失记录明确标注，不推定通过。确认动作仅计划部门可操作。销售可查看处理进度与通知；超时提示基于配置时长，不伪造真实通知发送。

## 5. 调整与版本

普通数量调整不走 OA、不再走领导审核，由计划部门确认留痕。执行开始前的其他内容调整走对应销售审核链，最后由计划部门确认。业务及组织归属不能在调整中改变；更换客户须符合原负责人及原组织范围。执行开始后非数量内容不提供普通变更入口。

每个计划最多一个未完结调整。独立变更单保存基准版本、调整前内容、拟调整内容、原因、处理人、审批记录、确认版本；“拟调整”不是当前执行版本。待确认或驳回时继续执行原数量；确认后生成 V2，保留 V1。并发基准版本变化必须重新核对，不覆盖其他窗口的新数据。

普通数量调整时限由规则管理员明确：执行开始前，或生产锁定前；未配置时不默认放行。已锁定/归档计划不能普通调整。现有订单净量作为减少数量的提示及下限校验，不能把缺失同步视为已执行零量。

## 6. 归属生效

客户归属变更记录生效日期、前后负责人及组织。不得追溯覆盖历史。未来日期到期后应用；发布清单保存归属快照。已经提交的在途批次由原负责人完成，原组织不变、不自动转交；已确认记录按原批次可追溯。新发布周期取当时生效主数据。已发布但未提交周期若需换负责人，须先处理清单变更，不允许新人越权填写旧清单。

## 7. 订单与售后统计

正式达成按下单时间落到北京时间自然日。发货、付款、同步日期不能替代。来源必须对应业务；下单时间缺失、商品/客户/渠道/单位无法映射、数量非法进入异常。订单行以平台＋订单号＋行号去重，更新快照优先；同时间冲突不计入并提示，不能重复累加。

有效订单状态由规则管理员按业务配置版本；取消排除。售后提供不回冲/按记录退货数量回冲选项；未确认口径不算正式达成。按记录退货回冲是原型演示方案，真实退货关联原订单行、跨月退货归属及退款不退货规则仍须业务确认。

完整同步范围、来源、时间和统计口径全部确认，才把无匹配订单认定为零；不完整显示待同步。多计划同类匹配不重复归因，正式达成标为待处理。月周分别归因，不相加。单位转换只可使用已维护商品标准系数，未映射保留原单位并列为异常。

订单明细展示原单、有效/取消、售后数量和统计口径，可从计划下钻。接口未真实接入；界面中的同步范围与异常是原型状态，不是已验证的平台结果。

## 8. 填报依据、历史销量与预测复盘

填报提供常规/促销/新品类型、需求依据、因素备注（活动、缺货、退货影响等）。促销/新品必须提供依据。历史销售有独立查询页和填报内弹窗，支持线下五维度、线上商品/渠道维度、日期范围及订单下钻。每日商品销量使用折线图；缺失日期不是零，模拟走势单独标明且不回写正式销售数据。

月末将本月月计划与覆盖本月的周计划比较。跨月周按本月重叠天数÷整周天数分摊，明确标为估算，不修改原计划。可选择原始预测/当前确认生效版本，展示周月差额、周月偏差率、正式实际销量、月/周预测偏差及高估/低估提示。正式实际缺口时不能断言预测正确。

复盘快照保存月份、业务、计划版本、销量同步与统计口径版本、归属快照和分摊结果。后续数据或规则变更不重写已保存结果。当前是可解释的偏差分析和填报参考，不声称已实现自动预测模型或保证预测准确。

## 全角色计划完成跟踪

填报人员的计划单、审核人员的下级汇总及商品/客户详情、计划部门的待确认/已确认任务列表和任务详情，均展示计划量、实际完成量、达成率、剩余量及超额量，并提供当前范围订单来源下钻。达成为下单销量，不是生产或发货完成；按当前生效版本计算，不把历史确认时点与当前销量混淆。

只有生效计划且同期同步完整、统计口径明确、订单匹配无冲突时计算正式达成。未生效、待同步、口径未确认分别说明原因；已同步原始订单量仅作参考，取消排除但不冒充正式净销量。汇总中有不具备条件的明细时不计算总体达成率，可单独展示已具备条件部分实际量；单位、业务和月周独立。所有数据保持当前角色可见范围。

## 9. 页面、演示与验收

入口：14 管理页、15 达成大屏、16 历史销售页；依赖全部在同一文件夹。复制整个文件夹，页面共享本地存储；跨页面稳定联动建议使用同源本地 HTTP。不同浏览器/文件 URL 的 localStorage 隔离是浏览器约束。

全流程演示页提供 2027 年十个独立周期固定批次样例，包含草稿、各级待审、待确认、生效、驳回、数量调整和无需求任务，不覆盖用户已有数据，也不自动配置销量口径。

侧栏固定、角色菜单稳定、窄屏抽屉；主区和表格自适应，宽表内部滚动。表单错误保留输入，键盘焦点可见，状态用文字表达，减少动态效果。当前验收脚本与结果见 README 和销售计划管理验收记录。

开发实现前仍须确认真实组织/商品/客户/渠道主数据、订单行唯一键、售后归属与单位换算。这些选择在原型中明确待配置，不以假设替代业务确认。
