## 推荐演示顺序

1. 在“查询与配置 / 全流程演示”点击“补充整单闭环演示数据”；2027 年独立周期样例不覆盖已有计划。
2. 点击节点“查看该节点”，自动进入对应演示角色和周期；可查看省区/大区/中心完整汇总、商品与客户明细。
3. 如要自己创建新的计划，先由规则管理员配置本期窗口、发布应填报清单；然后销售保存草稿、整单提交。
4. 销售审核结束后，计划部门确认任务才生效；普通数量调整同样等待确认，旧量不提前改变。
5. 正式达成须先确认线上/线下销量统计口径及同步范围；未配置显示待确认，不冒充真实达成。

月周独立、线上线下隔离；历史销售可在填报弹窗和独立页面查询。客户端角色是演示切换，不构成正式权限控制。

## 当前验收

在本目录执行 `node 销售计划管理-验收.cjs`。依赖工作区 Playwright 和 Microsoft Edge。测试使用独立浏览器上下文，不修改用户当前浏览器数据。旧流程单项脚本并非全部适用于 V4；统一入口是本版本的回归基准。
## 实际达成演示

原计划列表、审核列表、任务确认列表中的“查看达成演示”切换到2026年8月纯模拟数据，共48条线上/线下月周计划。覆盖0%、60%、100%、125%，袋、包、箱、盒分别显示；点实际销量查看模拟订单、退货和取消记录。“退出达成演示”恢复原数据查看。样例单独计算，不修改已有统计口径或同步范围。
## 加急调整测试申请

在“调整记录”或“演示案例”点击“补充6条加急调整测试申请”，查看2028年独立周期的增量、减量、换商品、中心处理中、驳回、确认生效样例；点击“查看申请”进入对应角色和周期。加急仅是优先标识，不新增OA或绕过原审批/确认。原有时限和减量订单下限校验仍生效，未配置时依然阻断确认。样例不覆盖原计划或配置。


## 角色首页（2026-10-13）

左侧“首页”展示当前角色的数据总览；在首页切换演示角色会继续停留在首页。省区看客户、线上运营看渠道，大区看省区、中心看大区、严总看中心、丹总看渠道；计划部门分别查看线上线下的确认任务，管理员查看商品或规则配置。

月度与周计划分开统计，周计划统计开始日在所选月份的记录，不与月度合并。数量按单位汇总，仅计角色权限内未归档计划，不含独立达成演示数据。“可整份审核”沿用完整汇总及发布清单校验，不等同于任意待审明细数量。首页仅导航，不直接审核或确认，不改变业务流程。
### 首页计划与实际统计（2026-10-14）

首页优先展示按角色维度与周期计算的计划汇总份数、商品明细条数、填报数量及已生效数量。实际完成、达成率和剩余/超额沿用原有订单统计，仅比较已生效计划，各单位单独计算；未同步或口径未确定时显示待同步/待确认。汇总表同排显示实际达成，并支持点击销量查看来源订单。汇总份数不是提交批次数，含草稿及流转中汇总；数量统计不合并月周或不同单位。
### 操作补充（2026-10-14）

保持原 UI 样式与审批规则，在填报、审核、任务确认、需求总表及首页表格旁增加搜索与“导出当前筛选结果”。搜索只影响查看，不改变审批批次；导出不包含状态筛选或关键词搜索隐藏的数据。批量审核选中项在被搜索隐藏时取消选择，防止误处理。

填报数量是包含已有订单的周期预计销售总量，不与订单再次相加。商品行展示历史参考摘要，日均与偏差需具备完整同步和已确认口径；按计划天数折算的参考量只是估算，不自动改计划。详情展示当前节点、最近退回意见、修改前后快照及订单来源/同步/口径说明。计划确认不是排程或交货承诺。

新验收：`node 计划操作补充-验收.cjs`，已加入统一验收入口。参考的另一份 HTML 保持原样，未修改。
### 审核退回区分（2026-10-14）

审核页分为“待审核”“本级已通过”“驳回待修改”。仍有退回明细的整份下级汇总只在驳回页展示，不混入待审核或已通过，不允许批量/单条审核。驳回页可区分本级及其他节点，展示退回范围、节点、时间、原因和销售修改职责；原因缺失明确提示核实。修改重提后按当前状态回到正常流程，历史驳回在详情保留。
### 线上两级审批（2026-10-14）

新增演示角色“线上领导”，线上流程为：线上运营 → 线上领导 → 丹总 → 计划部门确认生效。月周、无需求及内容调整采用同一线上销售审批链；普通数量调整仍直接交计划部门确认。

旧数据首次升级时在本机存储保存 `_backup_before_online_leader` 备份。已生效记录保留；未生效的旧线上计划补走线上领导初审，不伪造审批意见。可切换“线上领导”查看渠道计划、新首页及审核/驳回状态，固定批次演示中增加“线上待领导审核”。
### 加急处理可操作演示（2026-10-14）

打开 `18-加急处理测试演示.html` 自动补充十条加急申请，不覆盖已存在或已操作过的样例。点击“查看申请”进入当前处理角色；处理后从“演示案例”再次查看该申请，自动跳到下一节点，已确认自动切换已确认页。

建议先演示线下加急增量（1000→1400袋，由计划部门确认），再演示线上内容变更（1000→1200袋及换商品，线上领导→丹总→计划部门确认）。其他样例涵盖减量、中心/严总处理中、丹总待审、内容待确认、驳回及已确认。

仅命名空间 URGENT-DEMO 的测试单使用独立模拟配置：执行开始前可调整，模拟订单200袋、退货20袋，净执行下限180袋。该上下文仅用于验证调整规则，不写入正式订单、同步记录、销量口径或调整设置，也不作为正式销量。无效减量、锁定、归档、版本冲突及审批条件仍会阻断。加急不增加 OA 或改变业务链，确认前原量与 V1 不变。

### 加急申请入口（2026-10-14）

填报角色左侧“加急申请”→“发起加急申请”→选择关联原计划→选择数量调整或内容调整→填写差异及原因→提交。已确认原计划列表也有“加急申请”操作。申请独立留痕但不是另一份重复累计的生效需求，确认前原计划保持不变，确认后更新版本。数量调整直接交计划部门确认；内容调整沿用线下大区→中心→严总或线上领导→丹总，最后计划部门确认。未确认、锁定、归档或已有处理中申请的原计划不可发起。测试入口保留十条既有节点数据，新申请不冒充测试申请。

### 正式系统展示（2026-10-14）

默认隐藏角色职责长说明、阶段流程横幅、原型工具、推荐操作、模拟配置说明及重复的计划口径提醒，不删除数据和业务功能。保留字段标签、主操作、筛选、审批状态、确认数量差异、审批证据、空状态、错误原因和操作结果反馈。辅助说明使用 system-helper-hidden 展示层隐藏，不更改审核或生效规则。

### 演示准备数据（2026-10-14）

打开14主页面、15大屏或16历史查询时自动补充幂等样例：22个月/周固定批次节点、10条加急申请、48条实际达成样例，以及2026年9月和10月的逐日OMS/旺店通模拟订单（含取消、售后）。不覆盖已存在及已操作记录，不替正式数据修改销量口径或同步配置。

右上角“演示场景”按当前角色选择计划节点，自动定位周期；“实际达成”展示2026年8月独立模拟口径的0%、60%、100%、125%场景；“历史销售与订单”进入查询，可按商品、客户或渠道以及组织维度下钻。月、周审核确认仍相互独立。需完整演示线上链时切换线上领导→丹总→计划部门，线下切换大区→中心→严总→计划部门。规则和商品页面保留已有配置样例。历史销售的原始量可展示，未完整同步或未确认口径的数据不伪装成已确认净销量。
“演示场景 → 首页统计”可展示首页计划数、数量、实际完成与达成率；此视图仅选择独立模拟样例，不改变默认统计数据口径。订单关联页按计划预建匹配索引，销量归一化在单次页面渲染内复用，后续操作重新计算，避免较多测试数据导致重复计算。

### 计划部门销售分析与预估参考（2026-10-14）

计划部门新增“商品销售分析”“客户销售分析”入口。商品可分别查询线上/线下，自上线至今或最近30/90天、指定区间，线上按渠道、线下按中心筛选；客户仅线下，自签约至今或指定区间，并查看组织归属。上线日期与签约日期独立维护并留痕，不以首单或商品启用日期替代。原始量、退货、净销量、日均、最近订单与活跃天数按单位分行。

详情包含日/周/月趋势、商品对应客户或渠道构成、客户对应商品构成、分页订单及售后、预估参考。预估＝最近30/90天净销量÷完整参考天数×未来天数×业务调整系数；非零系数须填写依据，可保存区间、来源、参数和结果快照。新品样本不足、统计口径未确认或同步不完整时阻断。仅作为需求参考，不替代销售计划、不生成生产任务，也不包含库存、在制、产能及安全库存。

默认“模拟数据”独立生成完整历史，有新品和近期未下单客户；切换“业务数据”沿用OMS/旺店通原统计与同步配置。生命周期日期缺失时明确显示未维护，不冒充完整历史；模拟数据不写入原订单、计划或正式口径。停用商品仍可在业务历史中查询。单文件演示版同步包含上述页面。

### 角色工作台减负（2026-10-14）

销售常用菜单：首页、月度计划、周计划、调整记录；领导：首页、计划审核（销售计划/内容调整）；计划部门：首页、任务确认（全部/调整任务）、销售分析（商品/客户/计划达成/预测复盘）、预估记录。查询与进度折叠在次级入口；商品和规则维护仅相应角色展示。演示场景全部从右上角进入，导航不再单列加急或演示案例；原计划操作保留加急申请。通知和大屏/流程图放入头部“更多”。

小型详情表不再自动生成搜索导出，主列表和长表仍保留；填报明细次要操作收进“更多操作”，审核和确认主动作不隐藏。日期维护折叠，预估结果统一进入预估记录，减少分析页重复模块。月周计划、状态区分、权限、审核链、确认生效、历史留痕与原数据保持不变。

### 计划部门销售订单（2026-10-14）

次级菜单“订单异常”改为“销售订单”，只读展示现有OMS/旺店通订单号、行号、下单日期、客户或渠道、商品、单位、订单数量、退货数量、订单状态。支持线上/线下、日期、商品、状态、单位筛选及搜索导出。去掉计划关联匹配、异常处置和同步异常区块，保留底层统计与订单匹配规则，不修改数据或计划。

### 后台基础单位换算（2026-10-14）

统计基础单位只允许袋、罐、包、盒，箱是订单包装单位。原订单数量/单位、原退货数量保持不变；销量归一化、历史销售、实际达成及商品/客户分析先按后台箱规将订单和退货换算成基础单位，再执行有效状态、退货回冲、匹配和汇总。销售订单页并排展示原量与统计量、原退货与统计退货，以及箱规来源和版本。

接口原型约定 backendProductUnits 为后台商品单位记录数组：product、baseUnit、factors（如箱:20）、from、to、version、source。依据订单下单日期选择有效版本；同商品有效期重叠、换算比例无效或箱规缺失时不估算，显示待同步并阻止正式数量统计。界面不新增箱规维护操作，真实配置仍由现有后台管理。

本地演示订单有明确标记的模拟后台比例20；不会用于无demo标记的业务订单，也不代表实际后台配置。演示分析箱订单由模拟记录换算为基础单位。旧模拟计划的箱/支展示单位更新为罐/盒示例，数量仍为模拟基础单位数量；真实计划和原业务订单不作这种迁移。未对接真实后台接口。
