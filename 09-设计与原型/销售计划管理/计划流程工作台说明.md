# 计划管理工作台调整

主流程：我的填报（月 / 周独立）→ 我的审核（线下大区、中心、严总；线上丹总）→ 销售已确认需求 → 计划部门承接评估 → 销售确认承诺及缺口 → 冻结承诺 → 登记交付 → 月周预测复盘。

## 计划单与填报

线下按周期、中心、省区形成计划单；线上按周期、渠道形成计划单。整单包含客户商品明细，按单位分别汇总，不丢失原始ID、版本和审核记录。不同单位明细都保留在计划单中，不因统计单位被遗漏。

填报按周期范围、历史销售参考、商品数量、检查提交排列，最终提交需确认预览。上期已记录的复盘说明会在下一期填报展示。历史查询不离开当前表单，公共查询和配置归入辅助导航。

草稿直接编辑；首级尚未审核明细可以撤回；进入上级的内容通过开始前变更重新审批。驳回意见在计划单标明，重提从首级重新审核，旧记录不删除。已确认的数量调整继续由计划部门审核，不走OA；生产冻结后不允许普通修改。

## 审核

先展示本级待审核中的重复、历史缺失、需求依据缺失和较上期销售偏差提醒，再按原有商品汇总审核。偏差阈值默认30%，规则管理员可配置；提示不自动拒绝。驳回意见要求说明问题明细及修改要求。已审核与待审核继续分别展示。

## 承接与交付

销售需求量、生产承诺量、人工登记交付量独立保存。月周都是独立预测，只采用配置选定的生产承接周期，禁止相加。计划部门录入承诺数量、交期、库存/在制/物料/产能评估依据及缺口原因；原销售需求不覆盖。

销售确认或退回重评均需意见。销售确认后，计划部门填写冻结意见，再进入执行。承诺与销售版本绑定；需求版本变化显示待重评，不沿用旧承诺。旧承诺版本及审批留痕保留。实际交付人工登记，需要日期和凭据，累计不得超过承诺，日期不能在未来。

预测复盘按月份、业务记录偏差原因及下期改进。月周跨月天数估算分摊规则维持已确认口径。

## 边界与验收

仍是本机交互原型：没有真实身份鉴权、工厂产能、物料库存或物流接口；不自动判断生产可行性，不自动生成真实排产，不向外发送消息。冻结后的执行变更暂要求协调计划部门，不伪装为已完成外部审批。

`node 销售计划管理-验收.cjs` 包含新工作台、历史查询、月周复盘以及原有功能与9种宽度验收。旧测试选择器已随计划单和导航结构更新。
