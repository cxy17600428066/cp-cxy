# 最新确认规则

计划部门不审核销售需求，只确认任务；新计划与调整均在计划部门确认后生效。

- 新计划：销售填报 → 原销售审核链 → 待计划部门确认 → 已确认生效。
- 普通数量调整：申请 → 待计划部门确认 → 确认后更新执行数量及版本。不走OA，不提供通过/驳回。
- 开始前其他内容调整：原销售审核链审批 → 待计划部门确认 → 确认后更新内容及版本。
- 确认前原执行版本保持不变；尚未确认的新计划不进入生效需求、达成及复盘统计。
- 任务表区分待确认、已确认，保留确认人、时间、备注及版本差异。确认不改写销售需求；版本、冻结、数量等校验仍执行，防止冲突覆盖。

“计划任务确认”替代旧主流程中的计划部门审批和生产承诺评估入口。旧承接/交付记录保留，不删除，但不再作为销售计划生效的审批前置。

旧历史审核记录按历史事实保留；演示承接案例保留历史演示确认标记。正式接口、服务端权限和通知仍未接入。
