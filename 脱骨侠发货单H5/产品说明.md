# 脱骨侠发货单二维码 H5 产品方案

## 一、业务闭环

每个订单创建时生成唯一 `shipment_id`、发货单号和二维码。二维码只保存带随机令牌的短链接，例如：

`https://delivery.example.com/s/8fK2mP`

二维码不直接保存手机号、地址等敏感信息。扫码后由服务端根据订单状态和操作者身份返回当前可操作阶段。

1. 工厂物流人员：填写并提交发货信息。
2. 承运司机：到厂扫码，核验货物后提交揽收信息。
3. 承运司机：到达目的地扫码，提交签收与交接信息。
4. 甲方管理员：查看全链路凭证，确认收货或发起异常复核。

每个阶段只能按顺序提交。已提交记录只允许有权限的管理员走“更正申请”，保留原记录和修改痕迹。

创建发货单与确认发货分为两个状态：创建后先进入“待发货”，工厂完成逐商品数量、司机车辆、附件和现场凭证核验后再确认发货并开放司机揽收。订单计划、工厂发货、司机揽收、司机到货和甲方签收均按SKU保存独立数量；任一商品出现差异时必须填写异常类型、原因和照片，自动生成异常工单，支持短少、错货、破损、部分签收和拒收。

司机和车辆选择同时校验公司启停状态、驾驶证有效期、车辆年检和冷链资质。关键节点自动通知相关角色，超过预约揽收、预计到货或甲方确认时间后标记超时。节点提交采用幂等控制，提交中锁定按钮，防止网络重试造成重复记录。二维码令牌支持访问限频、立即作废和重新生成，旧令牌永久失效。

## 二、各阶段采集内容

### 工厂发货

- 发货仓、计划/实际发货时间、温控要求、物流公司、运输单号。
- 发货地址及发货单附件；附件支持图片或PDF，并与发货节点一起留存。
- 商品名称、SKU、69码、单包规格、口味、每箱包数、批次、生产日期、保质期、箱数、重量；数量统一按箱展示。
- 司机姓名、手机号、身份证后四位；车牌号、车辆类型、冷链资质有效期。
- 装车前车厢照片、车辆与车牌照片、货物码放照片、温度计照片、封签照片。
- 装车温度、封签号、工厂操作人签名。

### 司机揽收

- 揽收页展示当前发货单对应的客户/门店、收货联系人、联系电话、详细收货地址和预计送达时间，并提供一键拨号；信息由订单自动带入，只对绑定本单的承运司机展示。
- 揽收登记先展示从订单带入的商品数量核对区，包括商品名称、69码、单包规格、每箱包数、分商品箱数及总箱数/总包数，不向司机展示单价、成交金额等价格信息；核对完成后再填写现场核验信息。
- 扫码时间、自动定位、实际到厂/离厂时间、装车温度。
- 实收箱数，并逐项核对品名、批次、数量、包装、温度、封签。
- 工厂、司机揽收、司机到货、甲方签收分别保存独立的实际数量字段，不覆盖平台订单计划数量；每个业务节点首次点击确认后展示数量与责任人摘要，必须再次勾选确认才能提交。
- 车辆全景、货物码放、封签与车牌；建议读取原图时间和定位。
- 异常类型：数量差异、包装破损、温度异常、封签异常、车辆不符、其他。
- 异常描述、责任方、现场协商结果和补充图片。
- 司机确认承运与电子签名。

### 司机到货签收

- 到达时间、自动定位、与目的地的距离校验、轨迹异常提示。
- 开封前车厢温度、交付箱数、封签号复核。
- 车辆与仓门、开封前封签、卸货货物、温度计读数；异常时补充货损特写。
- 结果：正常交付、异常签收、拒收。
- 短少/破损/污染/解冻等异常数量、说明、现场处理结果。
- 现场收货人姓名、电话、电子签名和交接时间。

### 甲方确认

- 采用两步式操作：第一步集中查看商品明细、交付总览、实际现场照片和全程履约记录；核对后点击底部主按钮进入第二步，再填写签收数量、签收人、照片、签收单和核验项。第二步可随时返回详情，所有原始内容均保留。
- 汇总查看三个阶段的人员、时间、位置、温度、数量、照片和签名。
- 甲方确认签收时必填实际签收箱数、签收人姓名、手机号和签收照片；签收单附件选填，支持JPG、PNG、PDF。司机完成到货签收前，甲方确认按钮不可操作。
- 对比计划数、发货数、揽收数、签收数，自动标红差异。
- 确认结果：确认收货、部分确认、驳回复核。
- 填写验收意见、异常责任与赔付/补发结论。

## 三、权限与状态

建议状态：`待发货 → 已发货/待揽收 → 运输中/待签收 → 待甲方确认 → 已完成`，另设 `异常处理中`。

- 工厂物流使用姓名作为账号并通过密码登录；账号由管理员维护，只能提交发货阶段，提交后不能操作揽收、签收。
- 司机首次扫码需要手机号验证码，并校验是否为订单绑定司机。
- 甲方账号通过企业账号或验证码登录，只能确认自己公司的订单。
- 二维码可重复扫码查看进度，但同一阶段只允许提交一次。
- 发货单创建后、司机揽收前，工厂物流可从订单列表或发货单内发起司机变更，填写新司机、手机号、车辆和变更原因；系统解除原司机手机号绑定并重新绑定新司机。司机已揽收后须由后台管理员处理，所有变更保留前后值和操作记录。二维码泄露时支持后台立即作废令牌。

## 四、落地必做能力

- 服务端保存所有阶段数据，不能依赖浏览器本地存储。
- 图片上传对象存储，压缩展示图但保留原图；记录文件哈希、拍摄时间、上传时间和坐标。
- 所有提交生成操作日志：账号、角色、设备、IP、时间、前后数据。
- 定位仅做履约辅助，必须取得用户授权并展示隐私说明。
- 验证码、二维码令牌需限流；敏感字段在司机端脱敏显示。
- 断网时允许暂存草稿，恢复网络后提示用户主动提交，避免重复单据。
- 对数量差异、温度超限、定位偏差、封签不一致自动触发甲方预警。

## 五、本原型说明

直接用手机或桌面浏览器打开 `index.html` 即可体验。原型当前展示司机揽收场景，可切换查看发货单、到货签收和甲方确认，并支持本机选择照片、模拟定位、表单填写和提交反馈。

H5 登录后先进入对应角色的订单中心：工厂人员看到已接单订单并逐单创建发货单；移动端发货登记和揽收前司机变更均按照“物流公司 → 司机 → 车辆”联动选择，手机号和车型从后台档案自动带入，仅展示启用数据；司机手机号可绑定多张发货单并选择本次要操作的揽收/签收任务；甲方手机号可关联多张收货订单并逐单查看物流详情、完成确认。正式系统必须由后端按登录身份查询绑定关系，前端不能自行传入手机号获取任意订单。

使用桌面浏览器打开 `admin.html` 可体验物流管理后台，包括订单检索、状态筛选、每单二维码、四阶段节点详情、逐商品数量对账、照片凭证、异常工单、超时预警和更正审核。PC 端同时提供物流公司管理、司机与车辆管理：公司可新增、编辑、启停并查看关联司机；司机归属公司并关联车牌、车型、核载吨位、品牌型号及三类资质有效期。创建发货单时按“物流公司 → 司机 → 车辆”联动选择，手机号和车型自动带入，停用或资质过期数据不可使用。后台关键更正由申请管理员提交，另一管理员复核后才生效；正式系统应保留修改前后值、申请人、复核人、时间、IP和数据版本，禁止直接覆盖原始提交记录。

正式开发建议前端使用 Vue 3 / React，后端提供订单、身份验证、阶段提交、文件上传、定位、异常工单和操作日志接口。二维码建议在管理后台创建订单后生成并支持打印。
