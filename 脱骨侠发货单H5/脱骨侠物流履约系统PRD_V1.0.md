# 脱骨侠物流履约及发货单二维码系统 PRD

版本：V1.0（研发评审稿）  
编制日期：2026-08-10  
适用端：移动端 H5、PC 管理后台  
面向对象：产品、UI、前端、后端、测试、实施及业务运营

> 本文档以当前 H5 和 PC 管理后台原型为需求基线，描述正式系统的业务对象、页面功能、状态流转、数据规则、异常处理和验收标准。原型中的本地模拟数据、模拟短信、模拟定位和刷新后重置状态不属于正式实现方式。

## 1. 项目概述

### 1.1 项目背景

无骨鸡爪订单从工厂发货到客户最终确认，涉及工厂物流人员、外部承运司机、甲方收货人员和后台管理员。当前线下沟通难以保证数量、温度、车辆、照片、位置和签收资料完整留痕，也无法快速判断责任节点。

本项目通过“一订单、一发货单、一码贯穿全流程”的方式，将工厂发货、司机揽收、司机到货、甲方确认四个节点串联起来，并提供后台查询、异常处理、更正复核和承运资源管理能力。

### 1.2 产品目标

- 建立从平台订单到最终确认收货的完整线上履约链路。
- 每个业务节点形成不可覆盖的人员、时间、位置、数量和图片凭证。
- 通过司机手机号、甲方手机号和二维码完成订单授权绑定与快速访问。
- 按 SKU 保存订单计划、工厂发货、司机揽收、司机到货和甲方签收五套数量快照。
- 对数量差异、温度异常、定位偏差、封签不一致和资质过期进行自动拦截或预警。
- 后台支持全流程查看、二维码管理、承运资源管理、异常闭环及有审计记录的更正。

### 1.3 本期范围

- 移动端 H5：登录、角色订单中心、订单详情、创建发货单、发货登记、司机变更、揽收登记、到货签收、甲方查看与确认。
- PC 管理后台：物流订单、发货单详情、节点详情、二维码、异常工单、更正复核、物流公司、司机、车辆、资质、消息与超时。
- 系统能力：短信验证、订单同步、对象存储、定位、消息通知、审计日志、幂等提交和权限隔离。

### 1.4 非本期范围

- 订单支付、退款、对账和物流费用结算。
- WMS 库存扣减、库位管理和生产排程。
- 司机导航、路线规划和实时轨迹调度。
- 电子合同、保险理赔和第三方物流竞价。
- 对原 CRM 订单商品、价格或客户主数据的编辑。

## 2. 名词与业务对象

| 名词 | 定义 | 关键规则 |
|---|---|---|
| 平台订单 | 来自 CRM/订单平台的客户采购订单 | 商品、价格、客户和目的地址为只读源数据 |
| 发货单 | 为订单创建的物流履约单据 | 一个订单对应一张有效发货单 |
| 发货二维码 | 发货单的访问入口 | 二维码只包含随机令牌，不包含手机号、地址等明文 |
| 履约节点 | 工厂发货、司机揽收、司机到货、甲方确认 | 必须按顺序提交，已提交记录不可直接覆盖 |
| 绑定关系 | 发货单与司机手机号、甲方手机号的授权关系 | 同一手机号可绑定多张发货单 |
| 节点数量 | 某履约节点逐 SKU 的实际箱数 | 每个节点独立保存，不覆盖订单计划数量 |
| 现场凭证 | 节点上传的照片、附件、签名、定位等 | 保存原文件、哈希、上传时间和采集元数据 |
| 异常工单 | 数量、温度、定位、封签或货损异常的处理记录 | 与原履约记录并存，闭环处理不修改原始事实 |
| 更正申请 | 对已提交节点数据发起的受控修正 | 关键字段需双人复核并产生新数据版本 |

### 2.1 对象关系

- 平台订单与发货单为 1:1；一个订单只能存在一张有效发货单。
- 发货单与二维码为 1:1；二维码可重新生成版本，旧令牌永久失效。
- 发货单与履约节点为 1:4；每个节点默认只允许成功提交一次。
- 发货单与司机、甲方为多对一绑定；一个司机或甲方手机号可关联多张发货单。
- 发货单与异常工单、更正申请、通知和审计日志均为 1:N。

## 3. 角色与权限

| 角色 | 登录方式 | 可查看范围 | 可操作范围 |
|---|---|---|---|
| 工厂物流 | 姓名账号＋密码 | 已接单订单、本人有权限工厂的发货单及全部履约节点 | 创建发货单、发货登记、确认发货、揽收前变更司机 |
| 货车司机 | 手机号＋短信验证码 | 当前手机号绑定的全部发货单；客户收货联系信息 | 待揽收单的揽收登记、运输中单的到货签收 |
| 甲方收货 | 手机号＋短信验证码 | 当前手机号绑定的收货订单及其商品、物流详情和凭证 | 司机到货后填写签收资料并确认收货 |
| 后台管理员 | 后台账号＋密码/统一身份认证 | 全部订单、发货单、节点、资源、异常和日志 | 主数据维护、二维码管理、异常处理、更正申请 |
| 复核管理员 | 后台账号＋密码/统一身份认证 | 待复核更正及关联履约数据 | 审批或驳回关键字段更正，不得复核本人申请 |

### 3.1 通用权限规则

- 后端必须依据登录会话查询授权数据，禁止由前端传入任意手机号获取订单。
- 二维码不是免登录凭证。扫码后未登录时先进入登录页，登录成功后再校验角色、绑定关系和节点状态。
- 工厂可以查看全流程，但只能编辑待发货节点；司机只能编辑自己当前可操作的揽收或到货节点；甲方只能编辑待确认节点。
- 已完成、已作废或非当前节点的数据默认只读。
- 司机变更后，原手机号立即失去该发货单访问权限，新手机号获得权限；二维码仍对应原发货单。
- 后台手动修改不得直接覆盖原值，必须通过更正申请、复核和版本日志完成。

## 4. 端到端业务流程

### 4.1 主流程

1. 订单平台产生已接单订单，并同步订单、客户、商品、金额、目的地址和甲方手机号。
2. 工厂物流登录 H5，在订单列表查看平台订单详情，点击“创建发货单”。
3. 系统生成发货单草稿并进入待发货，工厂分三步登记发货信息、商品核对、司机与车辆。
4. 工厂上传发货单附件和装车凭证，确认逐 SKU 实际发货数量，完成二次确认。
5. 系统生成/激活二维码，绑定司机手机号，状态进入待揽收，并通知司机。
6. 司机登录或扫码选择发货单，先查看客户收货信息和商品数量，再完成到厂定位、温度、逐 SKU 数量及照片核验。
7. 司机二次确认揽收，状态进入运输中；若数量等存在差异，系统同时创建异常工单。
8. 司机到达目的地，提交位置、温度、到货数量、车辆/货物照片、现场收货人和电子签名。
9. 司机二次确认到货，状态进入待甲方确认，并通知甲方。
10. 甲方登录后分两步操作：第一步查看完整交付详情和实际照片；第二步填写逐 SKU 签收数量、签收人、手机号和签收照片。
11. 甲方二次确认收货，状态进入已完成；如部分签收或数量差异，异常工单继续独立闭环。

### 4.2 核心链路

平台已接单 → 创建发货单 → 待发货 → 工厂确认发货 → 待揽收 → 司机确认揽收 → 运输中 → 司机确认到货 → 待甲方确认 → 甲方确认 → 已完成

### 4.3 分支流程

- 司机变更：仅在司机未揽收前由工厂或管理员操作；揽收后只能由后台管理员按异常流程处理。
- 数量差异：任一 SKU 与上一节点不一致时，强制填写异常类型、差异原因和异常照片，再允许节点提交。
- 温度/定位/封签异常：依据配置执行阻断或警告，并创建异常工单。
- 部分签收/拒收：保存实际签收数量和交付结果，不回写订单计划数量，订单进入异常处理中或按业务规则完成。
- 二维码泄露/作废：管理员作废或重新生成二维码，旧令牌立即失效，履约数据不受影响。
- 数据录入错误：节点提交后通过后台更正申请处理；审批通过后生成新版本，原版本永久保留。

## 5. 状态机

### 5.1 发货单主状态

| 状态 | 进入条件 | 允许操作 | 下一状态 |
|---|---|---|---|
| 待创建 | 平台订单已接单但未创建发货单 | 查看订单、创建发货单 | 待发货 |
| 待发货 | 发货单已创建/草稿已保存 | 工厂填写、保存草稿、确认发货、变更司机 | 待揽收 |
| 待揽收 | 工厂发货节点已提交 | 司机揽收、工厂变更司机 | 运输中 |
| 运输中 | 司机揽收节点已提交 | 司机到货签收、查看物流 | 待确认 |
| 待确认 | 司机到货节点已提交 | 甲方查看详情、填写签收信息、确认收货 | 已完成 |
| 已完成 | 甲方确认成功 | 只读查看、异常处理、更正申请 | 已完成 |
| 异常处理中 | 任一节点存在未关闭异常 | 按原节点权限继续履约或等待处理 | 原主状态/已完成 |
| 已作废 | 管理员作废发货单 | 只读查看 | 无 |

### 5.2 状态控制规则

- 创建发货单与确认发货必须分离，创建后不得直接进入待揽收。
- 每次状态迁移与节点提交必须在同一数据库事务内完成。
- 节点接口校验当前状态，不允许跳级提交或重复提交。
- 异常处理中是业务标签，可与主状态并存；异常状态不得覆盖真实履约状态。
- 前端按钮状态只用于体验，最终权限和状态校验必须由后端完成。

## 7. 移动端详细需求

### 7.1 登录与订单中心

#### AUTH-001 角色登录

- 登录页提供工厂物流、货车司机、甲方收货三种身份。
- 工厂使用“姓名账号＋密码”登录，姓名为账号；账号、密码和启停状态由后台配置。
- 司机和甲方使用 11 位手机号＋6 位短信验证码登录。
- 验证码发送、验证、错误次数和频率限制由服务端控制。

#### AUTH-002 数据隔离

- 登录成功后按角色返回订单中心。
- 工厂按组织/工厂权限查询订单；司机和甲方按手机号有效绑定关系查询。
- 列表卡片展示订单/发货单号、客户、路线、数量、状态和预计时间。
- 支持全部、待处理、进行中、已完成筛选；进入详情后可返回原列表和筛选状态。

### 7.2 工厂订单详情与创建发货单

#### ORD-001 平台订单详情

- 展示平台订单号、买家、客户类别、销售区域、销售人员、订单类型、支付单号、发货主体、要求发货时间和订单状态。
- 展示商品名称、69 码、规格、口味、冷冻属性、保质期、箱数、成交价、小计及总金额。
- 展示收货人、联系电话和详细地址；敏感信息按角色权限脱敏。
- 页面只读，不展示发货、揽收、签收、甲方确认四个节点入口。
- 页面提供“创建发货单”主入口；已创建时显示“查看/继续发货登记”。

#### SHIP-001 创建发货单

- 校验订单不存在其他有效发货单后创建草稿。
- 创建成功生成发货单号，状态为待发货；二维码可在创建时生成待激活令牌，也可在确认发货时生成并激活。
- 自动复制订单客户、商品、甲方手机号、目的地址和要求时间快照。

### 7.3 发货登记

发货登记采用三个页签/步骤，已填写内容切换步骤时自动保留。

#### SHIP-002 第一步：发货信息

| 字段 | 类型 | 必填 | 数据规则 |
|---|---|---|---|
| 实际发货时间 | 日期时间 | 是 | 默认当前时间或要求发货时间，不得晚于服务端允许范围 |
| 运输方式 | 下拉 | 是 | 冷链运输、常温运输 |
| 发货仓库 | 下拉 | 是 | 卓希一号仓、卓希二号仓；正式系统由仓库字典配置 |
| 发货地址 | 只读文本 | 是 | 从订单目的地址自动带入，正式接口保留地址结构化字段 |
| 装车温度 | 数值 | 冷链必填 | 单位℃，按订单温控区间校验 |
| 封签号 | 文本 | 否 | 有封签时填写；后续节点用于一致性核验 |
| 发货单附件 | 文件 | 是 | JPG、PNG、PDF，单文件不超过 20MB |
| 发货备注 | 多行文本 | 否 | 温控、装卸和其他要求 |

#### SHIP-003 第二步：商品信息

- 商品从平台订单自动带入，不允许新增、删除或修改商品主信息及价格。
- 每个商品展示名称、SKU、69码、单包规格、口味、每箱包数、批次、箱数、重量、生产日期和保质期。
- 工厂逐 SKU 填写实际发货箱数，系统自动汇总总箱数并与订单计划数对比。
- 数量为 0 或正整数；如任一 SKU 存在差异，必须创建异常工单。

#### SHIP-004 第三步：司机、车辆与凭证

- 按“物流公司 → 司机 → 车辆”三级联动选择。
- 仅展示启用且资质有效的物流公司、司机和车辆。
- 选择司机后自动带入手机号，选择车辆后自动带入车牌和车型。
- 可填写运输单号；上传车厢装车前、货物码放、车牌车辆和温度计照片；有封签时上传封签照片。
- 确认发货前必须勾选信息核验声明。

#### SHIP-005 二次确认与提交

- 第一次点击“确认发货”后展示订单计划数量、工厂实际数量、物流公司、司机、手机号、车辆和附件摘要。
- 用户再次勾选确认声明并提交后，服务端保存节点记录、SKU 数量、凭证和状态。
- 提交成功后状态进入待揽收，绑定司机手机号并发送通知。
- 提交中按钮锁定；重复请求使用同一幂等键返回首次成功结果。

### 7.4 预约司机变更

#### SHIP-006 变更入口和限制

- 工厂订单列表和发货单详情均提供“变更司机”入口。
- 仅待发货、待揽收状态允许工厂变更；司机已揽收后只能由后台处理。
- 重新按物流公司、司机、车辆联动选择，必须填写变更原因并二次确认。
- 成功后保存原/新公司、司机、手机号、车辆、操作人和时间；解除旧手机号绑定并建立新绑定。
- 旧司机再次访问时提示“任务已改派”；新司机订单中心立即出现该任务。

### 7.5 司机揽收

#### PICK-001 客户收货信息

- 页面顶部展示客户/门店、收货联系人、完整联系电话、详细收货地址和预计送达时间。
- 提供一键拨打收货联系人电话；信息只对当前绑定司机可见。
- 切换发货单后必须刷新为对应订单数据，不允许沿用上一单信息。

#### PICK-002 商品数量核对

- 在现场表单之前展示商品名称、69码、单包规格、每箱包数、分商品箱数、总箱数和总包数。
- 司机端不展示商品单价、小计、总金额或其他商业价格。
- 司机逐 SKU 填写实际揽收箱数，系统与工厂发货数量逐项比较并自动汇总。

#### PICK-003 现场核验

- 记录实际揽收时间、现场经纬度、解析地址、定位精度和装车温度。
- 选择异常类型：无异常、数量不一致、包装/封签破损、温度异常、其他。
- 上传整车装货、货物码放、封签/车牌照片；保存原图及拍摄/上传元数据。
- 勾选货物、批次、数量、包装、温度和封签核验声明。

#### PICK-004 提交

- 第一次确认展示工厂数量、司机逐 SKU 数量和异常摘要。
- 二次确认成功后状态进入运输中，并通知工厂。
- 存在差异时，异常类型、原因和异常照片均为必填，提交节点同时生成异常工单。

### 7.6 司机到货签收

#### SIGN-001 到货信息

- 记录到达时间、经纬度、解析地址、定位精度和与目的地距离。
- 填写开箱前温度和逐 SKU 实际到货箱数，系统与司机揽收数量对比。
- 选择正常签收、异常签收或拒收；异常时填写短少、破损、温度等说明和现场结果。

#### SIGN-002 到货凭证与交接

- 上传车辆与仓门、开封前封签、卸货后货物照片；异常时补充货物特写和温度计照片。
- 填写现场收货人姓名和 11 位手机号，并完成电子签名。
- 签收位置超出目的地允许范围时按配置警告或禁止提交。

#### SIGN-003 提交

- 第一次确认展示司机揽收数量、实际到货数量和现场收货人摘要。
- 二次确认成功后状态进入待确认，并通知甲方。
- 拒收或数量差异需同步生成异常工单，原始到货数据不得被异常处理结果覆盖。

### 7.7 甲方查看与确认

#### BUY-001 甲方订单中心

- 甲方手机号登录后直接展示关联订单列表，不再提供独立“物流查询”表单。
- 运输中订单可查看进度；司机到货后开放完整详情和确认操作。
- 商品详情包含名称、69码、口味、规格、箱数、单价、小计和总金额。

#### BUY-002 第一步：查看交付详情

- 展示交付核验总览：工厂发货、司机揽收、司机到货数量，节点时间、温度、司机车辆和封签。
- 展示订单商品和全程履约时间线。
- 按发货、揽收、到货分组展示实际上传照片；点击缩略图查看大图，无图片时展示空状态。
- 底部按钮为“已核对详情，填写签收信息”。

#### BUY-003 第二步：填写签收确认

- 逐 SKU 填写实际签收箱数，系统与司机到货数量对比并自动汇总。
- 必填签收人姓名、11 位手机号和签收人与货物现场照片。
- 签收单附件选填，支持 JPG、PNG、PDF，单文件不超过 20MB。
- 勾选商品数量、履约凭证和到货品质三项核验声明；确认备注选填。
- 顶部步骤导航展示当前步骤，可随时返回第一步继续查看详情。

#### BUY-004 二次确认

- 第一次确认展示司机到货数量、甲方签收数量、签收人、照片及附件摘要。
- 二次确认成功后状态进入已完成，并通知工厂。
- 甲方实际签收数量与司机到货数量不一致时，必须填写部分签收/差异原因并上传异常照片。

## 8. 二维码、文件与现场留痕

### 8.1 二维码

- 每张发货单生成唯一随机高熵令牌，二维码 URL 不包含订单号、手机号和地址明文。
- 令牌记录版本、状态、创建时间、失效时间、最后访问时间和访问次数。
- 支持后台下载和打印，支持立即作废和重新生成；重新生成后旧令牌永久失效。
- 接口对令牌访问、短信发送和登录失败进行限频；无权限用户扫码只看到无权限提示。

### 8.2 文件与图片

- 文件先上传对象存储，再将文件 ID 与业务节点关联；数据库不保存二进制正文。
- 保存原文件、展示压缩图、文件哈希、MIME、大小、拍摄时间、上传时间、经纬度和上传人。
- 甲方凭证画廊读取实际节点文件，不允许使用占位图冒充现场照片。
- 删除或更换已提交凭证必须通过更正申请，原文件关系保留在历史版本。

### 8.3 操作审计

- 所有关键操作记录用户 ID、姓名、角色、组织、IP、设备标识、时间、请求 ID 和数据版本。
- 登录、查看敏感联系人、扫码、下载二维码、提交节点、司机变更、二维码作废、更正和复核均需审计。

## 9. PC 管理后台详细需求

### 9.1 物流订单与发货单

#### ADM-001 列表与查询

- 支持订单号、发货单号、客户、手机号、司机、车牌、物流公司和状态搜索。
- 支持工厂、创建时间、预计到货时间、异常、超时、二维码状态筛选。
- 展示路线、客户、司机车辆、最新节点、超时和异常标记；支持按筛选条件导出。

#### ADM-002 发货单详情

- 展示平台订单快照、发货单基础信息、收货信息、承运信息和二维码。
- 分别展示工厂发货、司机揽收、司机到货、甲方确认四个节点的表单、位置、照片、附件和提交人。
- 逐 SKU 对账展示订单计划、工厂发货、司机揽收、司机到货和甲方签收五列数量。
- 展示司机变更、异常、更正、通知和审计时间线。

#### ADM-003 后台创建和草稿

- 管理员可从已接单订单创建发货单，自动带入客户、路线、商品和甲方手机号。
- 未完成信息可以保存草稿；草稿不开放司机揽收。
- 确认发货仍需资质校验、附件校验和二次确认。

### 9.2 物流公司、司机和车辆

#### ADM-004 物流公司

- 新增、编辑、查询、启用和停用公司。
- 字段包括公司名称、统一社会信用代码、联系人、手机号、地址和备注。
- 公司停用后不可用于新发货单，历史履约快照保持不变。

#### ADM-005 司机与车辆

- 司机必须关联物流公司；字段包括姓名、手机号、驾驶证有效期、状态和备注。
- 一个司机可关联多辆车；车辆字段包括车牌、车辆类型、核载吨位、品牌型号、年检有效期和冷链资质有效期。
- 手机号和车牌需全局唯一或按业务配置唯一；停用/过期资源不可用于新发货。
- 新增、编辑和启停操作均需二次确认并写审计日志。

### 9.3 异常、更正与复核

#### EXC-001 异常工单

- 展示发货单、SKU、责任节点、异常类型、差异数量、原因、照片、创建人和处理状态。
- 支持待处理、处理中、待确认、已关闭、已驳回状态。
- 处理记录包含责任方、协商结果、补发/赔付说明、附件和操作时间。
- 关闭异常不得删除或修改原节点数据。

#### COR-001 更正申请

- 可对箱数、时间、温度、位置、人员、车辆、照片关系和业务状态发起更正。
- 必填更正原因和处理方式，界面并排展示原值与新值。
- 关键字段由另一名复核管理员审批；申请人不能审批自己的申请。
- 通过后生成新版本并更新当前展示值，原版本和审批意见永久保留。

### 9.4 二维码和消息

#### ADM-006 二维码管理

- 展示二维码、令牌版本、有效/作废状态、创建时间、最后访问和访问次数。
- 支持下载、打印、作废、重新生成；作废和重发均需二次确认。

#### ADM-007 消息与超时

- 汇总待揽收、预计到货、甲方确认超时和待处理异常数量。
- 支持查看通知发送结果、失败原因和手动重发。
- 关键订单可按责任人再次提醒。

## 10. 数量、异常与更正规则

### 10.1 逐 SKU 数量链

| 数量层级 | 数据来源 | 是否可覆盖上层 | 对比基准 |
|---|---|---|---|
| 订单计划数量 | CRM/订单平台 | 否 | 无 |
| 工厂实际发货数量 | 工厂发货节点 | 否 | 订单计划数量 |
| 司机实际揽收数量 | 司机揽收节点 | 否 | 工厂实际发货数量 |
| 司机实际到货数量 | 司机到货节点 | 否 | 司机实际揽收数量 |
| 甲方实际签收数量 | 甲方确认节点 | 否 | 司机实际到货数量 |

### 10.2 数量校验

- 数量单位统一按箱保存，逐 SKU 为 0 或正整数，总数由明细自动汇总。
- 每个节点提交时保存基准数量快照，避免上一节点后续更正导致历史比较失真。
- 差异不禁止业务继续，但必须先补充异常类型、原因和照片；是否阻断由异常级别配置。
- 页面突出显示差异 SKU 和差异箱数，后台同时支持五阶段横向对账。

### 10.3 提交与更正

- 业务节点提交使用 `shipment_id + stage + operator_id` 生成幂等键。
- 同一节点成功后再次请求返回首次结果，不产生重复节点、图片关系或通知。
- 已提交节点默认只读；更正通过版本机制生效，不更新原始提交记录。

### 11.1 快照原则

- 发货单创建时复制订单收货信息和商品信息快照，后续 CRM 主数据变化不影响已创建发货单。
- 确认发货时保存物流公司、司机、车辆和资质快照，历史页面不依赖当前主数据状态。
- 每个节点保存上一节点数量基准快照和本节点实际数量。

- 列表接口分页，详情接口按角色裁剪敏感字段；错误码区分未登录、无权限、状态冲突、版本冲突和参数错误。

## 13. 通知与 SLA

| 事件 | 接收角色 | 默认通知内容 |
|---|---|---|
| 发货单创建 | 工厂 | 发货单号、待补充项、要求发货时间 |
| 司机变更 | 原司机、新司机、工厂 | 改派结果、发货单号、车辆和操作时间 |
| 工厂确认发货 | 司机 | 发货单、客户、工厂地址、预约揽收时间 |
| 司机确认揽收 | 工厂 | 实际揽收数量、时间及异常提示 |
| 司机确认到货 | 甲方、工厂 | 到货时间、数量、待甲方确认提示 |
| 甲方确认完成 | 工厂、司机 | 实际签收数量和完成时间 |
| 异常创建/更新 | 工厂、甲方、管理员 | 异常节点、类型、状态和责任人 |
| 节点超时 | 当前责任人、管理员 | 超时节点、已超时长、处理入口 |

- SLA 节点至少包括预约揽收时间、预计到货时间和甲方确认期限。
- 超时后前后台标红并记录提醒次数；消息失败可重试，不能因通知失败回滚已成功节点。

## 14. 非功能与安全要求

### 14.1 性能与兼容

- H5 适配微信、企业微信及主流 iOS/Android 浏览器，设计宽度覆盖 320px 至 480px。
- 普通列表/详情接口在正常网络下 P95 响应时间不高于 2 秒；节点提交 P95 不高于 3 秒，不含文件上传时间。
- 图片展示使用缩略图和懒加载，大图按需加载；弱网下显示明确上传和重试状态。

### 14.2 可靠性

- 表单切换步骤时保存本地草稿；正式提交前以服务端状态和版本为准。
- 网络中断后不得显示提交成功；恢复网络时允许使用原幂等键重试。
- 节点记录、状态迁移、异常创建和绑定变化在事务内保持一致。

### 14.3 安全与隐私

- 密码加密存储，短信验证码短时有效且一次性使用；敏感接口启用限频和风控。
- 二维码令牌仅保存哈希，日志不得输出完整令牌、验证码或密码。
- 联系人、手机号、地址按角色和业务需要最小化展示；司机只在有效承运期间可见完整收货信息。
- 定位和相机使用前展示授权说明；文件访问使用有时效的授权 URL。
- 审计日志和原始履约记录不可由普通管理员删除。

## 15. 验收标准

### 15.1 主流程验收

1. 工厂能够从已接单订单进入只读订单详情，并创建唯一发货单。
2. 发货登记三个步骤可切换且数据不丢失，商品由订单带入且不能增删。
3. 工厂选择资质有效的物流公司、司机和车辆，上传必填附件后完成二次确认。
4. 司机手机号登录后能看到新任务，且能查看对应客户联系人、电话和详细地址。
5. 司机揽收页不显示任何商品价格，逐 SKU 数量与工厂数量可对比。
6. 司机完成揽收后才能操作到货签收，甲方在司机到货前不能确认。
7. 甲方确认页第一步只展示详情，第二步才展示填写项；可返回详情且内容不丢失。
8. 甲方完成二次确认后发货单状态为已完成，四节点数据均可在后台查看。

### 15.2 异常与安全验收

1. 任一 SKU 数量不一致时，未填写异常类型、原因和照片不能提交。
2. 司机变更后旧手机号无法查看该任务，新手机号可立即查看，变更日志完整。
3. 资质过期或停用的公司、司机、车辆不可用于确认发货。
4. 同一节点重复点击或网络重试只产生一条节点记录和一组通知。
5. 作废二维码不能访问；重新生成后旧二维码永久失效，新二维码正常访问。
6. 已提交数据不能直接覆盖；更正通过后可查看原值、新值、申请人、复核人和版本。
7. 无绑定关系的手机号即使获得二维码也不能查看订单敏感信息。
8. 甲方现场凭证展示实际上传文件，缺失时显示明确空状态。

### 15.3 后台验收

1. 管理员可按订单、发货单、客户、司机、车牌和状态检索物流数据。
2. 发货单详情可查看四节点和五阶段逐 SKU 数量对账。
3. 物流公司下可关联司机，司机下可维护多辆车辆和资质有效期。
4. 异常工单可记录处理过程并关闭，关闭后原始履约数据不变化。
5. 关键更正由非申请人复核后才生效，审计日志完整。

## 16. 原型边界与研发交付要求

### 16.1 当前原型边界

- H5 和 PC 页面是前端交互原型，刷新后新增数据、图片和状态恢复初始值。
- 当前短信验证码、定位、二维码、文件存储、消息和手机号绑定为模拟逻辑。
- 示例客户、手机号、地址、商品和图片仅用于演示，不作为生产数据。

### 16.2 研发交付物

- 前后端技术方案、数据库 ER 图、状态机和接口文档。
- H5、PC 管理后台、后端服务和数据库脚本。
- 对接订单、身份、短信、对象存储、定位和消息服务。
- 权限矩阵、错误码、审计方案、异常工单和更正版本方案。
- 单元测试、接口测试、核心 E2E 测试、部署文档和运维监控项。

### 16.3 上线前待业务确认

- 温控区间、目的地距离阈值和各异常级别的阻断策略。
- 单节点照片最少/最多数量、单张图片大小和允许格式。
- 预约揽收、预计到货和甲方确认的 SLA 时长及通知渠道。
- 部分签收、拒收和异常未关闭时，主状态是否允许进入已完成。
- 更正双人复核的关键字段范围及管理员角色分工。
- 发货单号、二维码有效期、仓库字典和运输方式字典规则。
